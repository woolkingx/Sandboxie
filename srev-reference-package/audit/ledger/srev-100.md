### SREV-100: Process Create Caller Snapshot

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official process-create notify, `PS_CREATE_NOTIFY_INFO`, legacy process notify, and ERESOURCE lock shape; needs Windows delegated-parent process-create runtime proof |
| Evidence | `Sandboxie/core/drv/process.c` decides whether a new process inherits sandbox state from the creator/caller or the inherited parent. Microsoft documents `PS_CREATE_NOTIFY_INFO.ParentProcessId` as the inherited parent and says it is not necessarily the process that created the new process; the creator process id is `CreatingThreadId->UniqueProcess`. Before this SREV, the Vista+ notify path passed `PsGetCurrentProcessId()` as `CallerId` even though `CreateInfo->CreatingThreadId.UniqueProcess` was the direct official identity edge. The nearby comment also described the parent lifetime issue as "cause us to crash" instead of naming the actual contract: clone needed sandbox state while `Process_ListLock` still protects the borrowed `PROCESS *`. |
| Data | `Sandboxie/core/drv/process.c`, `Process_NotifyProcessEx`, `PS_CREATE_NOTIFY_INFO.ParentProcessId`, `PS_CREATE_NOTIFY_INFO.CreatingThreadId.UniqueProcess`, legacy `Process_NotifyProcess`, `Process_NotifyProcess_Create`, `CallerId`, `ParentId`, `Process_Find`, `Process_ListLock`, `parent_proc->box`, `Box_Clone`, `Process_Delete`, and `Process_Map`. |
| Schema | `PROCESS_CREATE_CALLER_SNAPSHOT` says `ParentProcessId` is the inherited parent and not necessarily the creator; `CreatingThreadId.UniqueProcess` is the official creator/caller process id for Vista+ create notifications; legacy `PsSetCreateProcessNotifyRoutine` has only `ParentId` and current callback context, so it keeps `PsGetCurrentProcessId` as `CallerId`; `Process_Find(..., &irql)` returns while holding `Process_ListLock` shared; `Process_NotifyProcess_Create` must clone `parent_proc->box` before releasing `Process_ListLock`; `Process_Delete` removes and frees `PROCESS` state only after acquiring `Process_ListLock` exclusive; caller/parent selection must not dereference `parent_proc` after release. |
| Topology | Vista+ create notify now maps `CreateInfo->ParentProcessId` to `ParentId` and `CreateInfo->CreatingThreadId.UniqueProcess` to `CallerId` before entering `Process_NotifyProcess_Create`. The legacy XP notify path keeps `ParentId` plus `PsGetCurrentProcessId()` because that callback shape has no `PS_CREATE_NOTIFY_INFO`. In the inheritance path, `Process_Find(CallerId or ParentId, &irql)` holds `Process_ListLock` shared, `Box_Clone` copies `parent_proc->box`, the lock is released, and later code uses the cloned `BOX` rather than the borrowed `parent_proc`. `Process_Delete` needs the same lock exclusively before it can remove and free a `PROCESS`. |
| Logic Risk | Parent identity and creator identity are separate data edges. Keeping them distinct matters for AppInfo/RuntimeBroker-style delegated starts, explicit parent-process attributes, and sandbox escape prevention. The local lock discipline already made the borrowed parent pointer safe while cloning; the source comments now state that lifetime contract instead of merely naming a failure outcome. |
| Official Shape | `docs/plan/srev-100-process-create-caller-snapshot.md` records Microsoft `PsSetCreateProcessNotifyRoutineEx`, `PCREATE_PROCESS_NOTIFY_ROUTINE_EX`, `PS_CREATE_NOTIFY_INFO`, legacy `PsSetCreateProcessNotifyRoutine`, `ExAcquireResourceExclusiveLite`, and ERESOURCE references. `docs/plan/srev-100-process-create-caller-snapshot.schema.json` records the JSON Schema draft-07 local `PROCESS_CREATE_CALLER_SNAPSHOT` contract. |
| Fix | `Process_NotifyProcessEx` now passes `CreateInfo->CreatingThreadId.UniqueProcess` as `CallerId` to `Process_NotifyProcess_Create`; the debug comment was updated to say `caller`; the misleading static prototype parameter name was changed from `ParentId` to `Process`; the stale "cause us to crash" wording was replaced by a stable sandbox-state snapshot contract. The XP notify path, process-list lock order, and `Box_Clone` timing are unchanged. |
| Acceptance Gate | `docs/plan/check-srev-100.py` validates the draft-07 schema, official references, Vista+ caller identity source, legacy caller identity preservation, `Process_Find` shared-lock return shape, parent box clone before `Process_ListLock` release, `Process_Delete` exclusive removal/free topology, stale crash wording removal, and ledger entry; `docs/plan/check-srev-100.sh` is the matrix wrapper. Runtime gate: Windows process-create matrix with ordinary parent create, explicit parent-process attribute create, AppInfo/RuntimeBroker-style delegated create, sandboxed caller with non-sandbox inherited parent, non-sandbox caller with sandbox inherited parent, rapid parent exit during child creation, and Driver Verifier observation for process-list lock balance. |
