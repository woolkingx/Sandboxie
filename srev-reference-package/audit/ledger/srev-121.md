### SREV-121: User Server Duplicate Handle Result Gate

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official Win32 handle-duplication, APC enqueue, close-handle, and process-open shape; needs Windows service build/fault-injection proof |
| Evidence | `Sandboxie/core/svc/UserServer.cpp` was the highest-ranked unnamed reviewable core file after SREV-120. `UserServer::StartWorker` duplicated the service process handle into the worker process with `DuplicateHandle`, but wrapped that Win32 `BOOL` API in `NT_SUCCESS`. Since `FALSE` is zero and `NT_SUCCESS(0)` is true, a failed duplicate could still queue `UserServer__APC` with an uninitialized handle. `UserServer::OpenFile` also ignored the `DuplicateHandle` return value when duplicating a broker-opened file handle into the sandboxed caller, so a duplicate failure could leave `USER_OPEN_FILE_RPL.FileHandle` uninitialized while `rpl->error` still reflected a successful `NtCreateFile`. |
| Data | `UserServer::StartWorker`, `UserServer::OpenFile`, `DuplicateHandle`, `QueueUserAPC`, `OpenProcess`, `CloseHandle`, `NtCurrentProcess`, `pi.hProcess`, `pi.hThread`, `hThis`, `hProcess`, `hFile`, `USER_OPEN_FILE_RPL.FileHandle`, `rpl->error`, `PROCESS_DUP_HANDLE`, and `STATUS_UNSUCCESSFUL`. |
| Schema | `USER_SERVER_DUPLICATE_HANDLE_RESULT_GATE` says `DuplicateHandle` returns a Win32 `BOOL`, not an `NTSTATUS`; `DuplicateHandle` success is nonzero and failure is zero; `StartWorker` must not use `NT_SUCCESS` around `DuplicateHandle`; `StartWorker` queues `UserServer__APC` only after duplicate success; `StartWorker` closes the duplicate handle if `QueueUserAPC` fails; `OpenFile` initializes `USER_OPEN_FILE_RPL.FileHandle` to zero before duplication; `OpenFile` reports `STATUS_UNSUCCESSFUL` when duplicating the broker-opened handle into the caller process fails; this SREV does not change user-worker token selection, event security, file-policy path matching, requested access, `NtCreateFile` arguments, or queue routing. |
| Topology | `StartWorker` flows from a broker-owned service-process pseudo handle through `DuplicateHandle` into the worker process, then through `QueueUserAPC` to transfer the duplicated handle to the worker thread; if APC enqueue fails, the broker closes the duplicate it still owns. `OpenFile` flows from broker-side `NtCreateFile`, through `OpenProcess(PROCESS_DUP_HANDLE, caller pid)`, through `DuplicateHandle` into the caller process, then into `USER_OPEN_FILE_RPL.FileHandle`; failed handle crossing is represented by zero `FileHandle` plus `STATUS_UNSUCCESSFUL`, and the broker still closes its local file handle with `NtClose`. |
| Logic Risk | Treating a Win32 `BOOL` API as an `NTSTATUS` success code inverts the failure gate for zero-valued failure. In the worker-start path that can transfer an indeterminate handle value through APC; in the file-open broker path it can return a success-shaped reply without a valid caller handle. The correct local fix is a result gate at the existing handle boundary, not a policy change to who may start a worker, which file path rules apply, or which requested access flags are honored. |
| Official Shape | `docs/plan/srev-121-user-server-duplicate-handle-result-gate.md` records Microsoft `DuplicateHandle`, `QueueUserAPC`, `CloseHandle`, and `OpenProcess` references. `docs/plan/srev-121-user-server-duplicate-handle-result-gate.schema.json` records the JSON Schema draft-07 local `USER_SERVER_DUPLICATE_HANDLE_RESULT_GATE` contract. |
| Fix | `StartWorker` now initializes `hThis = NULL`, gates `QueueUserAPC` on nonzero `DuplicateHandle` success, and closes `hThis` if `QueueUserAPC` fails after the duplicate was created. `OpenFile` now initializes `rpl->FileHandle = 0` before `NtCreateFile` and sets `rpl->error = STATUS_UNSUCCESSFUL` if `DuplicateHandle` cannot duplicate the broker-opened file handle into the caller process. No user-worker token selection, event security descriptor, process creation flags, file-policy matching, requested file access, EA-buffer handling, `NtCreateFile` argument shape, broker-side `NtClose`, or queue callback routing changed. |
| Acceptance Gate | `docs/plan/check-srev-121.py` validates the draft-07 schema, official references, removal of `NT_SUCCESS(DuplicateHandle(...))`, worker APC enqueue gated on duplicate success, duplicate-handle cleanup on `QueueUserAPC` failure, `OpenFile` reply-handle zero initialization, duplicate-handle failure reported as `STATUS_UNSUCCESSFUL`, preserved broker-side `NtClose`, and ledger entry; `docs/plan/check-srev-121.sh` is the matrix wrapper. Runtime/build gate: Windows service build for `UserServer.cpp`, worker-start positive smoke proving the APC-transferred synchronization handle is usable, APC failure injection proving the duplicate is closed, sandboxed `USER_OPEN_FILE` positive smoke proving the duplicated handle works, and negative `OpenProcess` / `DuplicateHandle` smoke proving the reply carries `STATUS_UNSUCCESSFUL` with zero `FileHandle`. |
