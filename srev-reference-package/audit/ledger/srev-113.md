### SREV-113: Service Entry Resource Lifetime

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official SCM service entry, command-line, critical-section, and event-log handle lifetime shape; needs Windows SCM/proxy/event-log runtime proof |
| Evidence | `Sandboxie/core/svc/main.cpp` is the highest-ranked unnamed reviewable core file after SREV-112. Its `WinMain` initializes process-wide module state and `DriverAssist::InitializeSidCache`, then either dispatches proxy worker modes from the process command line or connects to the SCM with `StartServiceCtrlDispatcher`. The old source returned directly after each proxy worker returned and returned directly on `StartServiceCtrlDispatcher` failure, skipping `DriverAssist::DestroySidCache`. `InitializeEventLog` also opened a global event-log handle used by `LogEvent`, but service initialization failure after the open and STOP/SHUTDOWN cleanup did not close it. Microsoft documents `GetCommandLineW` as returning the process command-line string, `StartServiceCtrlDispatcher` as the SCM service-process boundary that returns failure through `GetLastError`, critical sections as requiring initialization before use and `DeleteCriticalSection` after initialization, and `OpenEventLog` handles as closed with `CloseEventLog`. |
| Data | `WinMain`, `_Ntdll`, `_Kernel32`, `_SystemInfo`, `DriverAssist::InitializeSidCache`, `DriverAssist::DestroySidCache`, `GetCommandLine`, `SANDBOXIE_ComProxy`, `SANDBOXIE_UacProxy`, `SANDBOXIE_NetProxy`, `SANDBOXIE_GuiProxy`, `SANDBOXIE_UserProxy`, `ComServer::RunSlave`, `ServiceServer::RunUacSlave`, `NetApiServer::RunSlave`, `GuiServer::RunSlave`, `UserServer::RunWorker`, `StartServiceCtrlDispatcher`, `ServiceMain`, `InitializeEventLog`, `OpenEventLog`, `EventLog`, `LogEvent`, `CloseEventLog`, `ServiceHandlerEx`, STOP/SHUTDOWN controls, `DriverAssist::Shutdown`, `MountManager::Shutdown`, and `SetServiceStatus`. |
| Schema | `SERVICE_ENTRY_RESOURCE_LIFETIME` says `WinMain` owns process-wide initialization before the service dispatcher or proxy worker path; `DriverAssist::InitializeSidCache` initializes a process-local critical section before service and proxy paths; every local return path from `WinMain` after SID cache initialization calls `DriverAssist::DestroySidCache`; proxy command-line detection order and proxy worker dispatch targets are unchanged; `StartServiceCtrlDispatcher` remains the SCM boundary for the normal service path; failed `StartServiceCtrlDispatcher` preserves `GetLastError` after SID cache cleanup; `InitializeEventLog` owns the event-log handle opened by `OpenEventLog`; opened event-log handles are closed with `CloseEventLog` on service initialization failure and STOP/SHUTDOWN cleanup; SCM status transitions, accepted controls, and proxy routing must not change. |
| Topology | Process entry flows from `WinMain` to process-wide module/system-info caching, `DriverAssist::InitializeSidCache`, optional command-line proxy routing, `finish`, `DriverAssist::DestroySidCache`, and return. Normal service startup flows through `StartServiceCtrlDispatcher`, `ServiceMain`, `RegisterServiceCtrlHandlerEx`, `SetServiceStatus(START_PENDING)`, `InitializeEventLog`, `DriverAssist::Initialize`, `InitializePipe`, and `SetServiceStatus(RUNNING)`. Initialization failure after event-log open closes `EventLog`, clears the global handle, and reports STOPPED. STOP/SHUTDOWN flows through `ServiceHandlerEx`, server/driver/mount cleanup, `CloseEventLog`, global handle clear, and `SetServiceStatus(STOPPED)`. |
| Logic Risk | Process-wide resource ownership was split across proxy and SCM topologies. The old source only cleaned the SID cache after successful dispatcher return, leaving proxy-return and dispatcher-failure paths without the matching critical-section cleanup edge. Event-log ownership had a similar missing edge: a successful `OpenEventLog` handle survived initialization failure and service stop cleanup. These are local lifecycle bugs, not a reason to alter proxy command-line markers, SCM table shape, service status values, accepted controls, server startup order, or log formatting. |
| Official Shape | `docs/plan/srev-113-service-entry-resource-lifetime.md` records Microsoft `GetCommandLineW`, `StartServiceCtrlDispatcherW`, ServiceMain, `RegisterServiceCtrlHandlerExW`, `SetServiceStatus`, critical section objects, `OpenEventLogW`, and `CloseEventLog` references. `docs/plan/srev-113-service-entry-resource-lifetime.schema.json` records the JSON Schema draft-07 local `SERVICE_ENTRY_RESOURCE_LIFETIME` contract. |
| Fix | `WinMain` now routes all local proxy-return paths and `StartServiceCtrlDispatcher` failure through a shared cleanup label after SID cache initialization. Proxy returns still return `NO_ERROR`; dispatcher failure still returns `GetLastError`; successful dispatcher completion still returns `NO_ERROR`. `ServiceMain` closes and clears `EventLog` if initialization fails after opening it. `ServiceHandlerEx` closes and clears `EventLog` during STOP/SHUTDOWN cleanup. No proxy marker matching, proxy dispatch targets, service table entries, `RegisterServiceCtrlHandlerEx`, `SetServiceStatus` state values, server startup, driver shutdown, mount-manager shutdown, or `LogEvent` formatting changed. |
| Acceptance Gate | `docs/plan/check-srev-113.py` validates the draft-07 schema, official references, `WinMain` SID cache cleanup topology, preservation of proxy routing and dispatcher error return, event-log handle cleanup on initialization failure and STOP/SHUTDOWN, and ledger entry; `docs/plan/check-srev-113.sh` is the matrix wrapper. Runtime gate: Windows SCM start/stop matrix, Com/UAC/Net/GUI/User proxy launch matrix, console/debug `StartServiceCtrlDispatcher` failure path, initialization failure after `OpenEventLog`, and event-log handle observation during STOP/SHUTDOWN and service restart. |
