### SREV-103: Win32k Current Thread GUI State

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official `IsGUIThread`, thread desktop connection, `PsGetCurrentThread`, and public kernel DDI index shape; needs Windows GUI-thread / direct win32k dispatch runtime proof |
| Evidence | `Sandboxie/core/drv/syscall_win32.c` directly dispatches win32k syscalls through `Sbie_InvokeSyscall_asm` after temporarily setting the thread token. The uncovered todo proposed calling private kernel conversion routines. Microsoft documents public GUI conversion through `IsGUIThread(TRUE)` for the calling thread, documents desktop connection as assigned to the thread making the connection, and documents `PsGetCurrentThread` as the current executive thread object. The public kernel DDI index does not document `PsConvertToGuiThread` or `KiConvertToGuiThread` as driver-callable DDIs. The old direct-dispatch guard used `PsGetProcessWin32Process(PsGetCurrentProcess())`, which proves process-level Win32 state but not current-thread Win32 state. |
| Data | `Syscall_Api_Invoke32`, win32k syscall indexes with `0x1000`, `Thread_SetThreadToken`, `handler1_func`, `Syscall_Invoke32`, `Sbie_InvokeSyscall_asm`, `PsGetProcessWin32Process(PsGetCurrentProcess())`, `PsGetThreadWin32Thread(PsGetCurrentThread())`, `STATUS_INVALID_ADDRESS`, trap-frame save/restore, and `Thread_ClearThreadToken`. |
| Schema | `WIN32K_CURRENT_THREAD_GUI_STATE` says `IsGUIThread` documents GUI state and optional conversion for the calling thread; Thread Connection to a Desktop assigns a desktop to the thread making the connection; `PsGetCurrentThread` returns the executive thread object for the current thread; `PsConvertToGuiThread` and `KiConvertToGuiThread` are not documented WDK DDIs and must not be called directly from this driver path; `Syscall_Api_Invoke32` direct win32k dispatch must use a current-thread Win32 state guard, not a process-level Win32 state guard; the source change keeps token setting, handler dispatch, direct syscall invocation, trap-frame restoration, and `STATUS_INVALID_ADDRESS` failure behavior intact. |
| Topology | `Syscall_Api_Invoke32` validates the sandboxed caller and win32k syscall index, may set the thread token, probes user arguments, takes `handler1_func` when owned by a handler, and otherwise requires `PsGetThreadWin32Thread(PsGetCurrentThread())` before `Syscall_Invoke32`. Direct dispatch still chooses `ntos_func2` only for configured filter-table use, otherwise `ntos_func`; the failure branch remains `STATUS_INVALID_ADDRESS`; cleanup still clears thread impersonation when needed. |
| Logic Risk | The stale todo named an internal conversion mechanism but not a legal driver boundary. Implementing it literally would add private kernel calls. The current source risk was that the guard checked process Win32 initialization even though the public GUI model and the local todo are both thread-shaped. A process can have Win32 state while a particular thread still lacks Win32 thread state, so direct win32k dispatch should be gated on the current thread. |
| Official Shape | `docs/plan/srev-103-win32k-current-thread-gui-state.md` records Microsoft `IsGUIThread`, Thread Connection to a Desktop, `PsGetCurrentThread`, and public kernel DDI index references. `docs/plan/srev-103-win32k-current-thread-gui-state.schema.json` records the JSON Schema draft-07 local `WIN32K_CURRENT_THREAD_GUI_STATE` contract. |
| Fix | `Syscall_Api_Invoke32` now requires `PsGetThreadWin32Thread(PsGetCurrentThread())` before direct win32k dispatch. The stale todo and obsolete `MmIsAddressValid` note were replaced with a private-boundary comment. No private GUI-thread conversion call, syscall table discovery change, handler change, or token cleanup change was added. |
| Acceptance Gate | `docs/plan/check-srev-103.py` validates the draft-07 schema, official references, current-thread GUI shape, private-call todo removal, guard replacement, preservation of dispatch/failure topology, supporting local declaration/comment evidence, and ledger entry; `docs/plan/check-srev-103.sh` is the matrix wrapper. Runtime gate: Windows x64/x86 matrix with sandboxed non-GUI current thread in a Win32-initialized process, sandboxed GUI current thread, `OpenWinClass` / win32k hook paths, `UseWin32kFilterTable` on/off, HVCI on/off, Driver Verifier, and observation that non-GUI current threads return `STATUS_INVALID_ADDRESS` rather than reaching direct win32k dispatch. |
