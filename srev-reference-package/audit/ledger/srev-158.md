### SREV-158: Ole HGLOBAL Lock And CIDA Copy Gates

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official `GlobalAlloc`, `GlobalLock`, `GlobalUnlock`, `STGMEDIUM`, `IDataObject::GetData`, and Shell `CFSTR_SHELLIDLIST` / `CIDA` shape review; needs Windows OLE clipboard and drag/drop runtime proof |
| Evidence | `Sandboxie/core/dll/ole.cpp` was the highest-ranked unnamed reviewable core file after SREV-157. It wraps OLE clipboard and drag/drop data objects, and its `XDataObject::GetData`, `InitFormatHDrop`, `InitFormatFileNameA`, `InitFormatFileNameW`, and `InitFormatIdList` synthesize or rewrite `TYMED_HGLOBAL` storage for `CF_HDROP`, `CFSTR_FILENAMEA`, `CFSTR_FILENAMEW`, and `CFSTR_SHELLIDLIST`. Before this SREV, several active paths dereferenced `GlobalLock` results without checking for `NULL`. The Shell ID List rewrite path also computed each child PIDL size from `GetPidl(count)` but copied bytes from the rewritten parent PIDL variable, so child CIDA offsets could point at parent bytes instead of the matching child PIDL. Microsoft documents `GlobalLock` as returning `NULL` on failure; documents `STGMEDIUM` as carrying `hGlobal` for `TYMED_HGLOBAL`; documents `IDataObject::GetData` as returning `STG_E_MEDIUMFULL` when a medium cannot be allocated; and documents `CFSTR_SHELLIDLIST` as a `CIDA` whose offset array contains the parent folder PIDL followed by one child PIDL offset per selected item. |
| Data | `Sandboxie/core/dll/ole.cpp`, `XDataObject::GetData`, `XDataObject::InitFormatHDrop`, `XDataObject::InitFormatFileNameA`, `XDataObject::InitFormatFileNameW`, `XDataObject::InitFormatIdList`, `GlobalAlloc`, `GlobalLock`, `GlobalUnlock`, `GlobalFree`, `STGMEDIUM`, `TYMED_HGLOBAL`, `CF_HDROP`, `CFSTR_FILENAMEA`, `CFSTR_FILENAMEW`, `CFSTR_SHELLIDLIST`, `CIDA`, `aoffset`, `GetPidl(0)`, `GetPidl(count)`, `pILGetSize`, `SHILCreateFromPath`, and sandbox path translation through `SbieDll_GetHandlePath`. |
| Schema | `OLE_HGLOBAL_LOCK_AND_CIDA_COPY_GATES` says every active `GlobalLock` result dereferenced by `ole.cpp` must be non-null before copy or API use; every successful active `GlobalLock` in these copy paths must be followed by `GlobalUnlock`; failed output `HGLOBAL` locks free the newly allocated handle before returning failure or `NULL`; `XDataObject::GetData` does not publish a caller-visible `STGMEDIUM` unless both source and destination locks succeed; `CFSTR_SHELLIDLIST` CIDA offset zero copies the rewritten parent PIDL and child offsets copy `GetPidl(count)`; and this SREV does not change supported clipboard formats, sandbox path translation policy, drag/drop scheduling, or inactive virtual-file extraction. |
| Topology | Legal `TYMED_HGLOBAL` rewrite flow is incoming medium or `HDROP`, size calculation, `GlobalAlloc(GMEM_MOVEABLE, size)`, source/destination `GlobalLock`, copy only after every required lock succeeds, `GlobalUnlock`, and publication through `STGMEDIUM` or replacement `HGLOBAL`. Legal Shell ID List flow is original `CIDA`, translated sandbox parent path, `SHILCreateFromPath` parent PIDL, new CIDA offset zero copying the translated parent PIDL, and each child offset copying the corresponding original `GetPidl(count)`. |
| Logic Risk | OLE consumers treat `STGMEDIUM` ownership and CIDA offsets as contracts. A failed `GlobalLock` followed by `memcpy` is a direct null-dereference class. Publishing a partially initialized medium leaks an invalid ownership state across the COM boundary. Copying parent PIDL bytes into child slots preserves byte counts but breaks the semantic topology of the Shell ID List. |
| Official Shape | `docs/plan/srev-158-ole-hglobal-lock-and-cida-copy-gates.md` records Microsoft `GlobalAlloc`, `GlobalLock`, `GlobalUnlock`, `STGMEDIUM`, `IDataObject::GetData`, and Shell clipboard `CFSTR_SHELLIDLIST` / `CIDA` references. `docs/plan/srev-158-ole-hglobal-lock-and-cida-copy-gates.schema.json` records the JSON Schema draft-07 local `OLE_HGLOBAL_LOCK_AND_CIDA_COPY_GATES` contract. |
| Fix | `XDataObject::GetData` now frees its newly allocated medium and returns `STG_E_MEDIUMFULL` unless both source and destination locks succeed. The HDROP, filename, and ID-list rewrite helpers now free their own output `HGLOBAL` and return `NULL` if an output lock fails; filename input locks now return `NULL` before `CreateFileA/W` if the incoming medium cannot be locked. The ID-list rewrite now copies `GetPidl(count)` for child entries instead of copying the parent PIDL bytes with child sizes. |
| Acceptance Gate | `docs/plan/check-srev-158.py` validates the draft-07 schema, official references, lock-before-copy gates in the active `GetData`, HDROP, filename, and ID-list paths, output-handle free-on-lock-failure behavior, `STG_E_MEDIUMFULL` failure before publishing `STGMEDIUM`, CIDA parent/child copy topology, stale parent-PIDL child copy removal, and ledger entry; `docs/plan/check-srev-158.sh` is the matrix wrapper. Runtime/build gate: Windows DLL build, clipboard and drag/drop smoke for `CF_HDROP`, `CFSTR_FILENAMEA`, `CFSTR_FILENAMEW`, and `CFSTR_SHELLIDLIST`, fault-injection or debugger-assisted `GlobalLock` failure proving no null dereference and no leaked replacement `HGLOBAL`, and Shell ID List parent/child PIDL resolution smoke. |
