### SREV-222: User Proxy Wire Buffer Bounds

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official Unicode string, `RtlInitUnicodeString`, `InitializeObjectAttributes`, `NtCreateFile`, and `ShellExecuteExW` shape review; needs Windows service/DLL build and malformed queue runtime proof |
| Evidence | `Sandboxie/core/svc/UserServer.h` and `Sandboxie/core/svc/UserWire.h` were top unnamed reviewable files after SREV-221. `UserServer::QueueCallbackWorker2` read `*(ULONG *)data_ptr` before proving `data_len >= sizeof(ULONG)`, while `QueueServer::PutReqHandler` allows nonzero request data lengths up to `PIPE_MAX_DATA_LEN`. `UserServer::OpenFile` and `UserServer::OpenDocument` trusted `FileNameOffset` before using the pointed data with `_wcsnicmp`, `wcslen`, `RtlInitUnicodeString`, `NtCreateFile`, and `ShellExecuteExW`; `OpenFile` also trusted `EaBufferOffset` / `EaLength`. On the producer side, `File_NtCreateFileProxy` copied `ObjectName->Length + sizeof(WCHAR)` from a counted `UNICODE_STRING` source buffer instead of copying only `Length` bytes and writing a local terminator. |
| Data | `QueueServer::PutReqHandler`, `SbieDll_QueueGetReq`, `UserServer::QueueCallbackWorker2`, `USER_OPEN_FILE_REQ`, `USER_SHELL_EXEC_REQ`, `FileNameOffset`, `EaBufferOffset`, `EaLength`, `UserServer::OpenFile`, `UserServer::OpenDocument`, `File_NtCreateFileProxy`, `ObjectAttributes->ObjectName`, `UNICODE_STRING.Length`, `RtlInitUnicodeString`, `NtCreateFile`, and `ShellExecuteExW`. |
| Schema | `USER_PROXY_WIRE_BUFFER_BOUNDS` says queue request data is caller-controlled wire data until the user proxy validates length and offsets; `QueueCallbackWorker2` may read `msgid` only after `data_len >= sizeof(ULONG)`; `USER_OPEN_FILE_REQ.FileNameOffset` and `USER_SHELL_EXEC_REQ.FileNameOffset` must point inside the received request buffer, after the fixed header, on a `WCHAR` boundary, and to a contained NUL-terminated string; nonzero `USER_OPEN_FILE_REQ.EaBufferOffset` must describe a range fully inside the received request buffer; `File_NtCreateFileProxy` copies exactly `ObjectName->Length` bytes from the counted source and synthesizes the NUL terminator locally; EFS policy, path-list matching, queue ownership, requested access, shell verb, and handle duplication topology are unchanged. |
| Topology | Sandboxed callers send opaque byte data through `SbieDll_QueuePutReq` to `QueueServer`, which stores the byte extent and later returns it to the user proxy worker through `SbieDll_QueueGetReq`. The user proxy owns the `UserWire.h` semantic layer: it validates the message id, fixed request header, bounded path string, and optional EA range before crossing into Windows `NtCreateFile` or `ShellExecuteExW`. The DLL producer owns conversion from a counted `UNICODE_STRING` object name to the local NUL-terminated wire string consumed by the worker. |
| Logic Risk | A short queue payload can make the worker read past the allocated request copy before it even knows which request handler to call. Malformed offsets can make the user proxy treat attacker-selected out-of-buffer bytes as a path or EA buffer. A counted `UNICODE_STRING` does not prove a readable trailing NUL exists at `Buffer + Length`, so producer-side `Length + sizeof(WCHAR)` copying can overread the caller buffer while preparing an otherwise valid request. |
| Official Shape | `docs/plan/srev-222-user-proxy-wire-buffer-bounds.md` records Microsoft `UNICODE_STRING`, `RtlInitUnicodeString`, `InitializeObjectAttributes`, `NtCreateFile`, `ShellExecuteExW`, and `SHELLEXECUTEINFOW` references. `docs/plan/srev-222-user-proxy-wire-buffer-bounds.schema.json` records the JSON Schema draft-07 local `USER_PROXY_WIRE_BUFFER_BOUNDS` contract. |
| Fix | `QueueCallbackWorker2` now checks `data_len < sizeof(ULONG)` before reading `msgid`. `UserServer.cpp` now uses `UserServer_GetWireString` for `USER_OPEN_FILE_REQ` and `USER_SHELL_EXEC_REQ` path offsets and `UserServer_GetWireRange` for the optional EA range, returning `STATUS_INFO_LENGTH_MISMATCH` for malformed wire shapes before path policy or Windows API calls. `File_NtCreateFileProxy` now rejects null object-name buffers, odd `UNICODE_STRING.Length` values, and request-size overflows, then copies exactly `ObjectName->Length` bytes and writes the local NUL terminator. |
| Acceptance Gate | `docs/plan/check-srev-222.py` validates the draft-07 schema, official references, short-message-id gate, bounded path and EA helpers, OpenFile/OpenDocument use of those helpers before Windows API calls, producer-side counted-string copy plus local terminator, stale `Length + WCHAR` source overread removal, and ledger entry; `docs/plan/check-srev-222.sh` is the targeted wrapper. Runtime/build gate: Windows service/DLL build for `UserServer.cpp` and `file.c`; malformed `USERPROXY` queue request smokes for data lengths 1-3, out-of-range/unaligned/pre-header/unterminated file-name offsets, and out-of-range EA spans; positive EFS `USER_OPEN_FILE` and `BreakoutDocument` smokes proving normal producer requests still work. |
