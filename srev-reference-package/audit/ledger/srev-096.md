### SREV-096: Clipboard Window-Station Reference Owner

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official window-station, Object Manager reference lifetime, clipboard delayed-rendering, and Mandatory Integrity Control shape; needs Windows UIPI clipboard runtime proof |
| Evidence | `Sandboxie/core/drv/gui.c` implements `API_GUI_CLIPBOARD` by taking the current process window-station handle, referencing the window-station object, and computing the private clipboard pointer at `Dyndata_Config.Clipboard_offset`. Microsoft documents a window station as a process-associated securable object that contains a clipboard. Microsoft documents `ObReferenceObjectByHandle` as returning an object-body pointer with the reference count incremented, and the object lifecycle contract says each such reference must be matched with `ObDereferenceObject` after the driver is done using the pointer. Before this SREV, `Gui_GetClipboard` dereferenced `WinStaObject` immediately before returning a pointer into the same object body, leaving `Gui_InitClipboard` and `Gui_FixClipboard` to read or modify private clipboard memory outside the held reference. |
| Data | `API_GUI_CLIPBOARD`, SbieSvc caller gate, current process window-station handle, referenced window-station object, private clipboard item list, `Dyndata_Config.Clipboard_offset`, layout discovery formats `0x111111` through `0x444444`, service integrity value `0x4000`, delayed-rendering force loop, and clipboard item integrity ULONGs. |
| Schema | `CLIPBOARD_WINDOW_STATION_REFERENCE_OWNER` says `API_GUI_CLIPBOARD` may inspect private clipboard state only from SbieSvc; the current process window-station handle is only a handle source; `ObReferenceObjectByHandle` must hold the window-station object while clipboard memory is read or modified; the returned clipboard pointer is valid only inside the held window-station reference scope; `Gui_InitClipboard` must release the reference on every exit after acquisition; `Gui_FixClipboard` must release the reference after mutating clipboard items; private clipboard layout discovery remains Dyndata/version gated; SbieSvc remains the clipboard open/lock and delayed-rendering owner. |
| Topology | `Gui_CloseClipboard` calls the SbieSvc GUI proxy after a clipboard sequence change. `GuiServer::CloseClipboardSlave` opens the clipboard, calls `API_GUI_CLIPBOARD(0x4000)`, enumerates formats, calls `GetClipboardData` to force delayed rendering, and closes the clipboard. In the driver, `Gui_Api_Clipboard` accepts only SbieSvc callers, references the current process window-station object, reads or mutates the private clipboard item list while the object reference is held, then releases the reference. |
| Logic Risk | The private win32k clipboard layout is still undocumented and runtime-version gated. This SREV does not pretend to make that layout official. The concrete bug is narrower: the Object Manager pointer lifetime did not match the official reference contract, so a stale or freed window-station object body could be used during clipboard layout discovery or IL mutation. |
| Official Shape | `docs/plan/srev-096-clipboard-window-station-reference-owner.md` records Microsoft window-station, `GetProcessWindowStation`, `ObReferenceObjectByHandle`, object lifecycle, clipboard delayed-rendering, `GetClipboardData`, clipboard operations, and Mandatory Integrity Control references. `docs/plan/srev-096-clipboard-window-station-reference-owner.schema.json` records the JSON Schema draft-07 local `CLIPBOARD_WINDOW_STATION_REFERENCE_OWNER` contract. |
| Fix | `Gui_GetClipboard` was replaced by `Gui_ReferenceClipboard` / `Gui_DereferenceClipboard`, returning a `GUI_CLIPBOARD_REF` that holds both the private clipboard pointer and the referenced window-station object. `Gui_InitClipboard` now uses a single `finish:` release path for all post-acquisition exits; `Gui_FixClipboard` releases the reference after the mutation loop. The SbieSvc-only gate, private layout discovery constants, `Dyndata_Config.Clipboard_offset`, delayed-rendering service loop, and integrity value policy are unchanged. |
| Acceptance Gate | `docs/plan/check-srev-096.py` validates the draft-07 schema, official references, SbieSvc-only gate, service-side delayed-rendering path, private layout discovery constants, removal of the stale immediate-deref-return shape, the new reference-scoped helper pair, reference release on all post-acquisition `Gui_InitClipboard` exits, reference release after `Gui_FixClipboard` mutation, and ledger entry; `docs/plan/check-srev-096.sh` is the matrix wrapper. Runtime gate: Windows Vista+ clipboard matrix with UAC/UIPI on/off, delayed rendering formats, ordinary immediate formats, viewer/listener notification race observation, service process `0x4000` integrity fix, and regression checks for copy from sandbox to host without system hang. |
