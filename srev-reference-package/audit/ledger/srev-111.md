### SREV-111: Driver Public Security And Private Handles

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official Windows driver security descriptor, ACL, MIC, private handle, `ZwOpenKey`, `ZwCreateFile`, and `ObReferenceObjectByHandle` shape; needs Windows driver-load / verifier runtime proof |
| Evidence | `Sandboxie/core/drv/driver.c` is the highest-ranked unnamed reviewable core file after SREV-110. Its driver-wide public security setup builds `Driver_PublicAcl`, `Driver_PublicSd`, and `Driver_LowLabelSd`, then other core paths consume those descriptors for file, IPC, key, and token-default-DACL operations. The old source ignored all `NTSTATUS` returns from `RtlCreateAcl`, `RtlAddAccessAllowedAceEx`, `RtlAddAce`, `RtlCreateSecurityDescriptor`, `RtlSetDaclSecurityDescriptor`, and `RtlSetSaclSecurityDescriptor`, so initialization could continue with partially built security descriptors. `Driver_FindHomePath` also opened private registry and file handles without `OBJ_KERNEL_HANDLE` before referencing the file handle with `ObReferenceObjectByHandle(..., KernelMode, ...)`. Microsoft documents ACL/security-descriptor DDIs as status-returning, Mandatory Integrity Control labels as SACL `SYSTEM_MANDATORY_LABEL_ACE` entries, private driver handles as `OBJ_KERNEL_HANDLE`, and `ObReferenceObjectByHandle(KernelMode)` as expecting a kernel-space handle. |
| Data | `Driver_InitPublicSecurity`, `Driver_PublicAcl`, `Driver_PublicSd`, `Driver_LowLabelSd`, Authenticated Users SID, Everyone SID, Restricted Code SID, `SYSTEM_MANDATORY_LABEL_ACE_TYPE`, `SYSTEM_MANDATORY_LABEL_NO_WRITE_UP`, `SECURITY_MANDATORY_LOW_RID`, `RtlCreateAcl`, `RtlAddAccessAllowedAceEx`, `RtlAddAce`, `RtlCreateSecurityDescriptor`, `RtlSetDaclSecurityDescriptor`, `RtlSetSaclSecurityDescriptor`, `Driver_FindHomePath`, `RegistryPath`, `ImagePath`, `ZwOpenKey`, `ZwQueryValueKey`, `ZwCreateFile`, `FILE_DIRECTORY_FILE`, `OBJ_KERNEL_HANDLE`, `ObReferenceObjectByHandle`, and `Obj_GetName`. |
| Schema | `DRIVER_PUBLIC_SECURITY_AND_PRIVATE_HANDLES` says `Driver_InitPublicSecurity` builds absolute security descriptors owned by the driver; ACL and security descriptor construction DDIs return `NTSTATUS` and must fail closed; `Driver_PublicAcl` keeps the existing compatibility DACL for Authenticated Users and Everyone; `Driver_LowLabelSd` keeps the Vista+ low-integrity SACL plus restricted-code DACL path; Mandatory Integrity Control stores an integrity label in an object's SACL through `SYSTEM_MANDATORY_LABEL_ACE`; `Driver_FindHomePath` creates only private driver handles for the registry key and installation directory; private registry/file handles are created with `OBJ_KERNEL_HANDLE`; `ObReferenceObjectByHandle(KernelMode)` is used only on the kernel-private file handle; SID values, access masks, descriptor consumers, and public object policy must not change. |
| Topology | Driver load calls `Driver_InitPublicSecurity`, which creates `Driver_PublicAcl`, assigns it to `Driver_PublicSd`, and on Vista+ builds `Driver_LowLabelSd` with a low mandatory-label SACL and Auth/World/Restricted DACL. Later consumers apply `Driver_PublicSd` to created file/IPC objects, apply `Driver_PublicAcl` as a token default DACL, and apply `Driver_LowLabelSd` through `ZwSetSecurityObject(LABEL_SECURITY_INFORMATION)`. Home-path discovery flows from `RegistryPath` to `ZwOpenKey(OBJ_KERNEL_HANDLE)`, `ZwQueryValueKey(ImagePath)`, canonicalized installation directory path, `ZwCreateFile(OBJ_KERNEL_HANDLE, FILE_DIRECTORY_FILE)`, `ObReferenceObjectByHandle(KernelMode)`, `Obj_GetName`, `ObDereferenceObject`, and `ZwClose`. |
| Logic Risk | A public or low-label descriptor that silently fails during construction undermines every downstream object that assumes that descriptor is valid. Because this is driver initialization, the correct local policy is fail-closed initialization rather than partial compatibility. Separately, missing `OBJ_KERNEL_HANDLE` is a handle-boundary smell even when DriverEntry normally runs in a system context; the correct contract is that the registry and file handles are private driver handles, and the later `KernelMode` object reference should only see a kernel-space handle. |
| Official Shape | `docs/plan/srev-111-driver-public-security-and-private-handles.md` records Microsoft Windows driver security model, SDDL for device objects, `RtlCreateAcl`, `RtlAddAccessAllowedAceEx`, `RtlCreateSecurityDescriptor`, `RtlSetSaclSecurityDescriptor`, Mandatory Integrity Control, Object Handles, `ZwOpenKey`, `ZwCreateFile`, and `ObReferenceObjectByHandle` references. `docs/plan/srev-111-driver-public-security-and-private-handles.schema.json` records the JSON Schema draft-07 local `DRIVER_PUBLIC_SECURITY_AND_PRIVATE_HANDLES` contract. |
| Fix | `Driver_InitPublicSecurity` now checks each ACL/security-descriptor construction `NTSTATUS` and returns `FALSE` on failure through the existing driver-entry failure path. `Driver_FindHomePath` now sets `OBJ_KERNEL_HANDLE` for the private registry key and installation-directory file handles. No SID bytes, access masks, descriptor storage, descriptor consumers, low-integrity label policy, service registry value parsing, canonical path lookup, or file-object reference behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-111.py` validates the draft-07 schema, official references, checked security-construction source shape, preservation of public/low-label descriptor nodes, private handle topology, stale non-kernel handle patterns, and ledger entry; `docs/plan/check-srev-111.sh` is the matrix wrapper. Runtime gate: Windows driver-load matrix with Driver Verifier enabled, allocation/failure injection for ACL/security descriptor construction, home-path registry/file open path during normal boot and service restart, low-integrity sandbox path creation, registry low-label application, and public descriptor consumers in file, IPC, token default-DACL, and key paths. |
