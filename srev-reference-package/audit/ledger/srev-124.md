### SREV-124: SbieApi Ioctl Close Request Boundary

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official native handle close, file open, and device-ioctl shape; needs Windows build/kmdutil runtime proof |
| Evidence | `Sandboxie/core/dll/sbieapi.c` was the highest-ranked unnamed reviewable core file after SREV-123. `SbieApi_Ioctl` uses a global cached `SbieApi_DeviceHandle` to open `API_DEVICE_NAME` with `NtOpenFile` and send synchronous driver API calls through `__sys_NtDeviceIoControlFile` or `NtDeviceIoControlFile`. The inline comment defines `parms == NULL` as a close request used by kmdutil. The old branch closed and invalidated the cached handle but then fell through into the trace and ioctl path, which reads `parms[0]`, can reopen the driver device, and can pass a null input buffer to the ioctl call. Microsoft documents `ZwClose` / `NtClose` as closing an object handle and returning an `NTSTATUS`, `NtOpenFile` as returning a file/device handle that must be closed when no longer in use, and `NtDeviceIoControlFile` as sending an ioctl to a specified file/device handle with an optional input buffer whose length must be zero when the buffer is null. |
| Data | `SbieApi_Ioctl`, `parms`, `parms[0]`, `SbieApi_DeviceHandle`, `INVALID_HANDLE_VALUE`, `NtClose`, `NtOpenFile`, `API_DEVICE_NAME`, `STATUS_OBJECT_NAME_NOT_FOUND`, `STATUS_NO_SUCH_DEVICE`, `STATUS_SERVER_DISABLED`, `Dll_SbieTrace`, `SbieApi_MonitorPutMsg`, `__sys_NtDeviceIoControlFile`, `NtDeviceIoControlFile`, `API_SBIEDRV_CTLCODE`, and `IO_STATUS_BLOCK`. |
| Schema | `SBIEAPI_IOCTL_CLOSE_REQUEST_BOUNDARY` says `SbieApi_Ioctl(NULL)` is a close request used by kmdutil; the close request closes the cached driver handle when one exists; the close request always invalidates `SbieApi_DeviceHandle`; the close request returns before trace, open, or device-ioctl logic can read `parms[0]` or reopen the driver device; the close request reports `NtClose` status when a handle existed, otherwise `STATUS_SUCCESS`; non-null requests preserve trace, driver-open, `STATUS_SERVER_DISABLED` remap, hook-bypass, and ioctl topology. |
| Topology | Close-request flow is now `SbieApi_Ioctl(NULL)` to optional `NtClose(SbieApi_DeviceHandle)`, cached-handle invalidation, and immediate return. Normal API flow remains non-null `parms`, optional trace using `parms[0]`, lazy `NtOpenFile(API_DEVICE_NAME)` when the cached handle is invalid, missing-driver status remap, and ioctl dispatch through `__sys_NtDeviceIoControlFile` or `NtDeviceIoControlFile` with `API_SBIEDRV_CTLCODE`. |
| Logic Risk | A close request and an ioctl request are opposite transitions at the cached driver-handle boundary. Falling through after close converted a lifecycle operation into a null-pointer read and could reopen the device immediately after closing it. The correct local repair is a terminal close branch, not a change to API argument marshalling, trace filtering, open access, missing-driver status mapping, hook bypass, or ioctl control code. |
| Official Shape | `docs/plan/srev-124-sbieapi-ioctl-close-request-boundary.md` records Microsoft `ZwClose` / `NtClose`, `NtOpenFile`, `NtDeviceIoControlFile`, and Nt/Zw native service references. `docs/plan/srev-124-sbieapi-ioctl-close-request-boundary.schema.json` records the JSON Schema draft-07 local `SBIEAPI_IOCTL_CLOSE_REQUEST_BOUNDARY` contract. |
| Fix | `SbieApi_Ioctl(NULL)` now initializes `status` to `STATUS_SUCCESS`, calls `NtClose` only when a cached handle exists, stores the `NtClose` status when it runs, invalidates `SbieApi_DeviceHandle`, and returns immediately. No non-null request trace logic, lazy driver open, missing-driver remap, hook-bypass selection, ioctl code, input-buffer shape, or return propagation changed. |
| Acceptance Gate | `docs/plan/check-srev-124.py` validates the draft-07 schema, official references, terminal close-request branch before trace/parms access, stale fallthrough close pattern removal, preservation of normal trace/open/remap/ioctl topology, and ledger entry; `docs/plan/check-srev-124.sh` is the matrix wrapper. Runtime/build gate: Windows build for `sbieapi.c`, kmdutil close-request smoke proving existing handles close without trace/open/ioctl fallthrough, null close request with no cached handle proving `STATUS_SUCCESS` and no reopen, and positive normal API call smoke proving unchanged trace filtering, lazy driver open, missing-driver remap, hook bypass, and ioctl request buffer shape. |
