### SREV-131: Process FindSandboxed Lock Release

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official ERESOURCE / IRQL release-shape review; needs Windows XP_SUPPORT driver runtime proof |
| Evidence | `Sandboxie/core/drv/process.h` was the highest-ranked unnamed reviewable core file after SREV-130. `Sandboxie/core/drv/process.c` implements `Process_Find` by raising IRQL to `APC_LEVEL`, acquiring `Process_ListLock`, and either releasing/lowering locally when `out_irql` is null or transferring the old IRQL and held lock to the caller when `out_irql` is non-null. `Process_FindSandboxed` wraps that API and filters host-injection processes by returning `NULL` for `proc->bHostInject`. Before this SREV, the filtered `NULL` path did not release `Process_ListLock` or lower IRQL when `Process_Find` had transferred ownership through `out_irql`. Microsoft documents `ExAcquireResourceSharedLite` as acquiring a resource and says it can be released with `ExReleaseResourceLite`; Microsoft documents `ExReleaseResourceLite` as releasing an executive resource owned by the current thread; Microsoft documents `KeRaiseIrql` as storing the original IRQL for later `KeLowerIrql`; Microsoft documents `KeLowerIrql` as restoring the IRQL value returned by the preceding raise call. |
| Data | `Sandboxie/core/drv/process.h`, `Sandboxie/core/drv/process.c`, `Process_Find`, `Process_FindSandboxed`, `Process_ListLock`, `Process_Map`, `PROCESS`, `PROCESS_TERMINATED`, `out_irql`, `KIRQL irql`, `KeRaiseIrql`, `KeLowerIrql`, `ExAcquireResourceSharedLite`, `ExReleaseResourceLite`, and `proc->bHostInject`. |
| Schema | `PROCESS_FINDSANDBOXED_LOCK_RELEASE` says `Process_Find` owns the `Process_ListLock` and raised-IRQL transfer contract when `out_irql` is non-null; `Process_Find` raises to `APC_LEVEL` and acquires `Process_ListLock` before returning a protected `PROCESS *`; `Process_Find` without `out_irql` releases `Process_ListLock` and lowers IRQL before return; `Process_Find` with `out_irql` stores the old IRQL for the caller and leaves `Process_ListLock` held; `Process_FindSandboxed` may filter a found `PROCESS` when `bHostInject` is set; filtered `NULL` after `bHostInject` releases `Process_ListLock` and lowers IRQL when `out_irql` is non-null; direct `NULL` misses and `PROCESS_TERMINATED` sentinel behavior are preserved; successful sandboxed `PROCESS` ownership and caller-release topology are unchanged. |
| Topology | Legal flow is `Process_Find(..., &irql)`, raise to `APC_LEVEL`, acquire `Process_ListLock`, find `PROCESS`, write `*out_irql`, and transfer caller-owned release/lower while the caller inspects the protected process. The corrected host-inject filter path is `Process_FindSandboxed(..., &irql)`, `Process_Find` transfers lock/IRQL, `proc` exists and is not `PROCESS_TERMINATED`, `proc->bHostInject` is true, release `Process_ListLock`, lower IRQL using `*out_irql`, then return `NULL`. Direct misses and `PROCESS_TERMINATED` returns keep their existing semantics. |
| Logic Risk | `Process_FindSandboxed` changes "found process" into "no sandboxed process" for host-injection records. Returning `NULL` while still transferring lock/IRQL state leaves the caller with no process object but a hidden kernel cleanup obligation, which can leak `Process_ListLock` ownership or keep IRQL raised on future use of the wrapper contract. The correct owner-local repair is to balance the lower-level transfer only on the filtered path, not to alter sandbox membership policy or the `PROCESS_TERMINATED` sentinel. |
| Official Shape | `docs/plan/srev-131-process-findsandboxed-lock-release.md` records Microsoft `ExAcquireResourceSharedLite`, `ExReleaseResourceLite`, `KeRaiseIrql`, and `KeLowerIrql` references. `docs/plan/srev-131-process-findsandboxed-lock-release.schema.json` records the JSON Schema draft-07 local `PROCESS_FINDSANDBOXED_LOCK_RELEASE` contract. |
| Fix | `Process_FindSandboxed` now releases `Process_ListLock` and lowers IRQL through `*out_irql` before returning `NULL` for a `bHostInject` filtered process when the caller requested the locked return contract. Normal sandboxed process returns, direct misses, and `PROCESS_TERMINATED` returns are unchanged. |
| Acceptance Gate | `docs/plan/check-srev-131.py` validates the draft-07 schema, official references, `Process_Find` lock/IRQL transfer shape, `Process_FindSandboxed` host-inject filter shape, release/lower ordering before `proc = NULL`, preservation of direct miss and `PROCESS_TERMINATED` topology, stale filtered-NULL-without-release shape removal, header declaration, and ledger entry; `docs/plan/check-srev-131.sh` is the matrix wrapper. Runtime/build gate: Windows driver build with `XP_SUPPORT` enabled for `process.c`, normal sandboxed lookup proving caller-owned release remains intact, `bHostInject` filtered lookup proving `NULL` return does not leak `Process_ListLock` or raised IRQL, `PROCESS_TERMINATED` lookup proving sentinel behavior is unchanged, and Driver Verifier or kernel debugger observation proving no leaked ERESOURCE ownership. |
