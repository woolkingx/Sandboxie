### SREV-120: Terminal User Token Session Contract

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official WTS session-token and handle-duplication shape; needs Windows Terminal Services runtime proof |
| Evidence | `Sandboxie/core/dll/terminal.c` was the highest-ranked unnamed reviewable core file after SREV-119. Its `Terminal_WTSQueryUserToken(ULONG SessionId, HANDLE *pToken)` hook accepted the official `SessionId` parameter but sent only a bare `MSG_HEADER` through `Sandboxie/core/svc/terminalwire.h` to `Sandboxie/core/svc/terminalserver.cpp` `TerminalServer::GetUserToken`. The service then derived the caller process session through `SbieApi_QueryProcess` and called `WTSQueryUserToken(session_id, &hToken)`. Microsoft documents `WTSQueryUserToken` as obtaining the primary access token of the logged-on user specified by the session ID, warns that highly trusted services must not leak user tokens, and documents returned token handles as caller-close owned. Microsoft documents `DuplicateHandle` as duplicating a valid source handle into a target process handle that has `PROCESS_DUP_HANDLE`. |
| Data | `Sandboxie/core/dll/terminal.c`, `Sandboxie/core/svc/terminalwire.h`, `Sandboxie/core/svc/terminalserver.cpp`, `Terminal_WTSQueryUserToken`, `GET_USER_TOKEN_REQ`, `GET_USER_TOKEN_RPL`, `SessionId`, `req->session_id`, `TerminalServer::GetUserToken`, `PipeServer::GetCallerProcessId`, `SbieApi_QueryProcess`, caller session id, `WTSQueryUserToken`, `API_FILTER_TOKEN`, `OriginalToken`, `UnfilteredToken`, `DuplicateHandle`, `PROCESS_DUP_HANDLE`, `TOKEN_ALL_ACCESS`, and `CloseHandle(hToken)`. |
| Schema | `TERMINAL_USER_TOKEN_SESSION_CONTRACT` says `WTSQueryUserToken` is keyed by an explicit Remote Desktop Services `SessionId`; `Terminal_WTSQueryUserToken` must forward the caller requested `SessionId` in `GET_USER_TOKEN_REQ`; `TerminalServer::GetUserToken` validates the full `GET_USER_TOKEN_REQ` size; TerminalServer only satisfies the request when requested session equals the `SbieApi_QueryProcess` caller session; TerminalServer calls `WTSQueryUserToken` with the validated requested session id; token filtering, `OriginalToken`, `UnfilteredToken`, `DuplicateHandle`, and close-handle ownership are unchanged. |
| Topology | A sandboxed process calls `Terminal_WTSQueryUserToken(SessionId, pToken)`, which sends `GET_USER_TOKEN_REQ { MSG_HEADER, session_id }` to TerminalServer. The service resolves the pipe caller pid, queries Sandboxie process state for the caller session, rejects mismatched requested sessions with `ERROR_ACCESS_DENIED`, calls `WTSQueryUserToken(req->session_id, &hToken)` only after that gate, optionally filters the token through `API_FILTER_TOKEN`, duplicates the resulting token handle into the caller process, closes its local token handle, and returns the duplicated handle in `GET_USER_TOKEN_RPL`. |
| Logic Risk | Dropping `SessionId` at the wire boundary made the hook return a token for the caller-derived session even when the caller asked for a different session. Passing the requested session directly to the trusted service without a caller-session gate would create the opposite bug: a sandboxed caller could ask the LocalSystem broker for another session's user token. The correct local boundary is explicit requested-session data plus same-session authorization before the trusted WTS call. |
| Official Shape | `docs/plan/srev-120-terminal-user-token-session-contract.md` records Microsoft `WTSQueryUserToken`, `WTSEnumerateSessionsW`, and `DuplicateHandle` references. `docs/plan/srev-120-terminal-user-token-session-contract.schema.json` records the JSON Schema draft-07 local `TERMINAL_USER_TOKEN_SESSION_CONTRACT` contract. |
| Fix | `GET_USER_TOKEN_REQ` now carries `ULONG session_id`. `Terminal_WTSQueryUserToken` writes its `SessionId` argument into that field. `TerminalServer::GetUserToken` now validates `sizeof(GET_USER_TOKEN_REQ)`, rejects requests whose `req->session_id` differs from the caller process session returned by `SbieApi_QueryProcess`, and calls `WTSQueryUserToken(req->session_id, &hToken)` after that gate. No token filtering policy, `OriginalToken` / `UnfilteredToken` configuration, `API_FILTER_TOKEN` routing, `DuplicateHandle` target process, token close path, or reply handle shape changed. |
| Acceptance Gate | `docs/plan/check-srev-120.py` validates the draft-07 schema, official references, `GET_USER_TOKEN_REQ` wire shape, DLL-side forwarding of the requested session id, service-side full request-size validation, same-session authorization gate, validated `WTSQueryUserToken(req->session_id, ...)` call, preserved token filtering / duplication / close-handle topology, stale bare-header validation removal, stale caller-derived WTS argument removal, and ledger entry; `docs/plan/check-srev-120.sh` is the matrix wrapper. Runtime/build gate: Windows build for `terminal.c`, `terminalwire.h`, and `terminalserver.cpp`; sandboxed `WTSQueryUserToken(Dll_SessionId, ...)` smoke proving the duplicated token handle is usable and caller-closed; negative different-session request smoke returning `ERROR_ACCESS_DENIED`; `OriginalToken`, `UnfilteredToken`, and filtered-token policy matrix; and 32-bit / 64-bit caller-service handle-duplication matrix. |
