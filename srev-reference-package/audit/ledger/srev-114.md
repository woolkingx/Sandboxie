### SREV-114: SCM Service Key Path Shape

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official SCM service-name, service-handle, service-registry-key, object-attributes, `NtOpenKey`, and `NtCreateKey` shape; needs Windows SCM/name-length runtime proof |
| Evidence | `Sandboxie/core/dll/scm.c` was the highest-ranked unnamed reviewable core file after SREV-113. Its `Scm_OpenServiceWImpl` accepts a service name, invalidates registry merge cache for the Services root and service subkey, opens boxed services through `Scm_OpenKeyForService`, queries host services through SbieSvc, then creates a local pseudo-`SC_HANDLE` with a `tzuk` marker followed by the service-name payload. The old source built `\REGISTRY\MACHINE\SYSTEM\CurrentControlSet\Services\<ServiceName>` in a fixed 128-WCHAR stack buffer in `Scm_OpenKeyForService`, and built the same path in a fixed 256-WCHAR temp buffer in `Scm_DiscardKeyCache`. Microsoft documents `OpenServiceW` service names as up to 256 characters, case-insensitive, and not display names; `CreateServiceA` documents the service key created under `HKEY_LOCAL_MACHINE\System\CurrentControlSet\Services`; `InitializeObjectAttributes` takes a Unicode object name for open/create routines; and `ZwOpenKey` / `ZwCreateKey` consume an `OBJECT_ATTRIBUTES` path and return handles. |
| Data | `Scm_OpenServiceWImpl`, `lpServiceName`, `SCM_SERVICE_NAME_MAX_CHARS`, `Scm_DiscardKeyCache`, `Scm_IsBoxedService`, `Scm_OpenKeyForService`, `Scm_QueryServiceByName`, local `SC_HANDLE` payload, `tzuk`, `Scm_AllocServiceKeyPath`, `Scm_ServicesKeyPath`, `Key_UpdateMergeByPath`, `RtlInitUnicodeString`, `InitializeObjectAttributes`, `NtOpenKey`, `NtCreateKey`, `KEY_QUERY_VALUE`, `KEY_ALL_ACCESS`, `ERROR_INVALID_NAME`, `ERROR_NOT_ENOUGH_MEMORY`, and `RtlNtStatusToDosError`. |
| Schema | `SCM_SERVICE_KEY_PATH_SHAPE` says `OpenServiceW` service names are non-empty and at most 256 characters; Sandboxie local service handles store a `tzuk` marker followed by the service-name payload; lower-casing applies only to the service-name payload and not to the marker; service registry paths are composed from `Scm_ServicesKeyPath`, slash, and service name; service registry path buffers are sized from actual base path and service name length; `Scm_OpenKeyForService` owns the temporary path buffer until `NtOpenKey` or `NtCreateKey` returns; `Scm_DiscardKeyCache` invalidates Services root and service subkey while preserving caller last error; access masks, boxed-service lookup, SbieSvc query routing, key-cache invalidation targets, and handle marker layout must not change. |
| Topology | `Scm_OpenServiceWImpl` validates `HANDLE_SERVICE_MANAGER`, validates non-empty service name, rejects names longer than `SCM_SERVICE_NAME_MAX_CHARS`, calls `Scm_DiscardKeyCache`, chooses boxed-service registry lookup or SbieSvc host query, allocates a local pseudo-handle, writes the `tzuk` marker, copies the service-name payload, and lower-cases only that payload. `Scm_AllocServiceKeyPath` owns the `Services\ServiceName` string composition. `Scm_OpenKeyForService` uses the helper path with `RtlInitUnicodeString`, `InitializeObjectAttributes`, `NtOpenKey` or `NtCreateKey`, maps status to Win32 last-error values, and frees the temporary path. `Scm_DiscardKeyCache` updates the Services root merge cache, then updates the service subkey merge cache when a legal path can be built, and restores the incoming last-error value. |
| Logic Risk | The old fixed buffers were shorter than the legal upstream data shape once the service-registry base path and separator were included. That turns a valid or near-valid SCM service name into local memory corruption before `NtOpenKey` / `NtCreateKey` can return a normal error. The old `_wcslwr(name)` also treated marker-plus-payload memory as one wide string; the local handle schema is marker first, string second, so string transforms must start at the payload pointer. |
| Official Shape | `docs/plan/srev-114-scm-service-key-path-shape.md` records Microsoft `OpenServiceW`, `CreateServiceA`, `CloseServiceHandle`, `InitializeObjectAttributes`, `ZwOpenKey`, `ZwCreateKey`, and registry element size-limit references. `docs/plan/srev-114-scm-service-key-path-shape.schema.json` records the JSON Schema draft-07 local `SCM_SERVICE_KEY_PATH_SHAPE` contract. |
| Fix | `Scm_OpenServiceWImpl` now rejects service names longer than `SCM_SERVICE_NAME_MAX_CHARS`, checks the local handle allocation, and lower-cases only the service-name payload after the marker. New `Scm_AllocServiceKeyPath` centralizes length-derived service registry path allocation. `Scm_OpenKeyForService` and `Scm_DiscardKeyCache` use that helper instead of fixed stack/temp buffers. `Scm_DiscardKeyCache` preserves the caller-visible last-error value because cache invalidation is not the public result of the SCM operation. No access masks, boxed-service classification, SbieSvc query routing, `NtOpenKey` / `NtCreateKey` status mapping, key-cache invalidation targets, or local handle marker layout changed. |
| Acceptance Gate | `docs/plan/check-srev-114.py` validates the draft-07 schema, official references, service-name length validation, dynamic service-key path helper, `Scm_OpenKeyForService` ownership/free topology, `Scm_DiscardKeyCache` last-error preservation, removal of old fixed buffers, payload-only lower-casing, and ledger entry; `docs/plan/check-srev-114.sh` is the matrix wrapper. Runtime gate: Windows matrix for `OpenServiceW` / `OpenServiceA` with short, 128-char, 255-char, 256-char, and 257-char names; boxed-service registry-key open with near-limit names; key-cache invalidation observation; invalid slash/backslash/empty/over-limit names; and existing BITS/WUAU/MSIServer/TrustedInstaller/CryptSvc compatibility paths. |
