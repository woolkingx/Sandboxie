### SREV-132: Low ARM64 Entry Syscall ABI Contract

| Field | Content |
|---|---|
| Severity | [minor] |
| Status | reviewed source-level ABI/topology classification after official Windows ARM64 / ARM64EC ABI review; needs Windows ARM64 and ARM64EC runtime proof |
| Evidence | `Sandboxie/core/low/entry_arm.asm` was the highest-ranked unnamed reviewable core file after SREV-131. It exports `SystemServiceARM64`, `NtDeviceIoControlFileEC`, `DeviceIoControlSvc`, `EcExitThunkPtr`, `DetourCodeARM64`, and `SbieLowData`. `SystemServiceARM64` spills incoming `x0-x7` syscall arguments, records the syscall index from `x17`, builds an `API_INVOKE_SYSCALL` parameter block, and calls the local `SBIELOW_DATA.NtDeviceIoControlFile` pointer. `Sandboxie/core/low/init.c` patches the `ServiceDataPtr` slot immediately before `SystemServiceARM64`, and in ARM64EC mode routes `data->NtDeviceIoControlFile` to `NtDeviceIoControlFileEC`, copies the native `svc` instruction into `DeviceIoControlSvc`, and writes `EcExitThunkPtr` from the syscall extra-data trailer. Microsoft documents the Windows ARM64 volatile/non-volatile register split and 16-byte stack-alignment requirement. Microsoft documents Arm64EC as interoperating with x64 code in the same process, and describes entry/exit thunks and call-checker mediated ABI transitions. |
| Data | `Sandboxie/core/low/entry_arm.asm`, `Sandboxie/core/low/init.c`, `Sandboxie/core/low/lowdata.h`, `SystemServiceARM64`, `ServiceDataPtr`, `NtDeviceIoControlFileEC`, `DeviceIoControlSvc`, `EcExitThunkPtr`, `MyHandleStubHijack`, `DetourCodeARM64`, `SbieLowData`, `SBIELOW_DATA`, `api_device_handle`, `api_sbiedrv_ctlcode`, `api_invoke_syscall`, `NtDeviceIoControlFile`, `NtDeviceIoControlFile_code`, `RealNtDeviceIoControlFile`, `syscall_data`, `x0-x17`, `sp`, `fp`, `lr`, and `API_NUM_ARGS`. |
| Schema | `LOW_ARM64_ENTRY_SYSCALL_ABI_CONTRACT` says `SystemServiceARM64` is an ARM64 syscall bridge that follows the Windows ARM64 volatile register and 16-byte stack-alignment contract; it spills original `x0-x7` syscall arguments before repurposing `x0-x7` for `NtDeviceIoControlFile`; it records the syscall index from `x17` and the original argument-stack pointer in `API_NUM_ARGS` slots; it builds the `NtDeviceIoControlFile` call with `x0-x7` plus two stack arguments and returns the call status in `x0`; `PrepSyscalls` patches the `ServiceDataPtr` slot immediately before `SystemServiceARM64`; ARM64EC routing points `data->NtDeviceIoControlFile` to `NtDeviceIoControlFileEC`, copies the native `svc` instruction into `DeviceIoControlSvc`, and writes `EcExitThunkPtr`; `NtDeviceIoControlFileEC` branches through `MyHandleStubHijack` only when the emulator changes the sentinel; this SREV does not change syscall detour bytes or ARM64EC thunk policy. |
| Topology | ARM64 syscall flow is patched `Zw*` export, `SystemServiceARM64`, spill original syscall args, `x17` syscall index plus original argument-stack pointer, `API_INVOKE_SYSCALL` parameter block, `SBIELOW_DATA.NtDeviceIoControlFile`, `SbieDrv` `API_SBIEDRV_CTLCODE`, and NTSTATUS return in `x0`. ARM64EC flow is `PrepSyscalls` seeing `is_arm64ec`, `data->NtDeviceIoControlFile = NtDeviceIoControlFileEC`, `DeviceIoControlSvc` receiving the native `svc` instruction, `EcExitThunkPtr` receiving the extra-data trailer thunk pointer, `NtDeviceIoControlFileEC` taking the `svc` path, and optional `MyHandleStubHijack` emulator exit path. |
| Logic Risk | This is a high-blast-radius assembly boundary: register volatility, stack alignment, `SBIELOW_DATA` offsets, syscall index handoff, and Arm64EC thunk routing are all part of the legal shape. Source review did not expose a surgical defect, so changing bytes would be worse than recording the ABI contract. Future changes must be driven by Windows ARM64 / ARM64EC runtime evidence, not by x64/x86 analogy. |
| Official Shape | `docs/plan/srev-132-low-arm64-entry-syscall-abi-contract.md` records Microsoft Windows ARM64 ABI, Arm64EC ABI, and Arm64EC interoperability references. `docs/plan/srev-132-low-arm64-entry-syscall-abi-contract.schema.json` records the JSON Schema draft-07 local `LOW_ARM64_ENTRY_SYSCALL_ABI_CONTRACT` contract. |
| Fix | No source behavior changed. `Sandboxie/core/low/entry_arm.asm` is now ledger-named with its ARM64 / ARM64EC syscall bridge contract and source gate. |

Runtime/build gate: Windows ARM64 lowlevel build, ARM64 sandbox process startup proving `SystemServiceARM64` stack and status behavior, ARM64EC process startup proving `NtDeviceIoControlFileEC` and `EcExitThunkPtr` routing, syscall hook smoke proving original `x0-x7` arguments reach `API_INVOKE_SYSCALL`, and disabled-hook smoke proving no ARM64EC wrapper state is used when `is_arm64ec` is false. |
