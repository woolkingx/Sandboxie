### SREV-112: ComServer Slave IPC Open Lifetime

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official named event, mutex, file mapping, mapped-view, handle close, COM initialization, and COM security shape; needs Windows COM proxy runtime proof |
| Evidence | `Sandboxie/core/svc/comserver.cpp` is the highest-ranked unnamed reviewable core file after SREV-111. Its `ComServer::RunSlave` opens parent-created IPC objects by name, maps the shared request/reply area, initializes COM, dispatches requests, and signals the parent reply event. The old source opened `Event2` into `hEvent2` but checked `hEvent1` again; if the reply event open failed while the request event succeeded, the slave entered the COM loop and later called `SetEvent(hEvent2)` with a NULL handle, leaving the parent blocked on the reply event. The same startup path returned directly after opening handles or mapping a view, and suffix replacement assumed the proxy command line contained a colon separator. Microsoft documents `OpenEvent` / `OpenFileMapping` as returning handles that should be closed, mapped views as requiring `UnmapViewOfFile`, file mappings as requiring view unmap plus handle close, and `CoInitializeEx` as required before COM library calls with successful calls balanced by `CoUninitialize`. |
| Data | `ComServer::RunSlave`, `cmdline`, `Global\\`, `Mutex`, `Event1`, `Event2`, `Map`, `OpenMutex`, `OpenEvent`, `OpenFileMapping`, `MapViewOfFile`, `COM_SLAVE_MAP`, `m_heap`, `HeapCreate`, `HeapDestroy`, `CoInitializeEx`, `CoInitializeSecurity`, `CoUninitialize`, `WaitForMultipleObjects`, `SetEvent(hEvent2)`, and parent-side `LockSlave` `CreateMutex` / `CreateEvent` / `CreateFileMapping` / `CreateProcessAsUser`. |
| Schema | `COMSERVER_SLAVE_IPC_OPEN_LIFETIME` says `RunSlave` accepts only a bounded parent-generated proxy command line; the command line must contain the colon separator before object-name suffix replacement; the slave opens the parent-created mutex, request event, reply event, and file mapping by name in the Global namespace; `Event1` is the request event waited by the slave; `Event2` is the reply event signaled by the slave after writing `pMap`; each opened kernel handle is closed on startup failure; each mapped view is unmapped on startup failure; `CoInitializeEx` must succeed before COM library calls; successful `CoInitializeEx` is balanced by `CoUninitialize` on the local cleanup path; object names, access masks, COM request dispatch, and parent-death `ExitProcess` behavior must not change. |
| Topology | Parent service creates named `Mutex`, `Event1`, `Event2`, and `Map` objects and launches `SbieSvc.exe` with the same proxy command-line stem. The slave validates the command-line length and colon separator, opens `Global\\...Mutex`, `Global\\...Event1`, `Global\\...Event2`, and `Global\\...Map`, maps `COM_SLAVE_MAP`, initializes heap and COM STA state, then waits on parent mutex or `Event1`. A request flows from `pMap->msgid` through the corresponding COM slave dispatcher, writes `pMap->exc` / `pMap->hr`, and signals `Event2`. Startup failures flow through one cleanup block that uninitializes COM when initialized, destroys the heap, unmaps the view, and closes opened handles. |
| Logic Risk | `Event1` and `Event2` are opposite edges in the request/reply protocol. Checking the wrong handle after opening `Event2` transforms a failed reply channel into a parent-side hang. Returning directly from partial startup also hid ownership edges for named handles and mapped views. Finally, treating the colon separator as implicit made malformed command-line data a null-pointer write path before any object open failed cleanly. |
| Official Shape | `docs/plan/srev-112-comserver-slave-ipc-open-lifetime.md` records Microsoft `OpenEventW`, `OpenFileMappingW`, `MapViewOfFile`, file-mapping close, `CloseHandle`, `UnmapViewOfFile`, `CoInitializeEx`, `CoInitializeSecurity`, and mutex object references. `docs/plan/srev-112-comserver-slave-ipc-open-lifetime.schema.json` records the JSON Schema draft-07 local `COMSERVER_SLAVE_IPC_OPEN_LIFETIME` contract. |
| Fix | `RunSlave` now rejects a malformed command line without a colon, checks `hEvent2` after opening the reply event, routes startup failures to a cleanup block, unmaps mapped views, closes opened mutex/event/file-mapping handles, checks `CoInitializeEx`, and balances successful local COM initialization with `CoUninitialize` on cleanup. No parent object creation, object naming, access masks, COM request ids, shared-map layout, dispatch handlers, `CoInitializeSecurity` arguments, or normal parent-death `ExitProcess` behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-112.py` validates the draft-07 schema, official references, `RunSlave` colon validation, Event1/Event2 request-reply topology, corrected Event2 failure check, mapped-view/handle cleanup, checked `CoInitializeEx`, preserved dispatch/ExitProcess path, and ledger entry; `docs/plan/check-srev-112.sh` is the matrix wrapper. Runtime gate: Windows COM proxy startup with normal IPC objects, negative startup matrix for missing Mutex/Event1/Event2/Map, parent wait observation proving `Event2` is signaled after successful dispatch, COM apartment initialization failure injection, and resource observation for mapped-view and handle cleanup on startup failure. |
