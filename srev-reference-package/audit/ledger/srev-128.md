### SREV-128: GUI XP Hook Trampoline Failure Lifetime

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official pool allocation/free lifetime shape and local trampoline NULL-return shape; needs Windows XP hook runtime proof |
| Evidence | `Sandboxie/core/drv/gui_xp.c` was the highest-ranked unnamed reviewable core file after SREV-127. `Gui_HookService` builds trampolines for XP GUI and IPC service hooks, optionally patches a SpySweeper push-jump trampoline, publishes `*pSourceFunc = Trampoline`, builds a hook entry, and then modifies kernel code under MDL/DPC freeze control. `Hook_BuildTramp` in `Sandboxie/core/dll/hook_tramp.c` can return `NULL` when instruction analysis fails, trampoline allocation fails, or trampoline copy fails. The old code wrote through `Trampoline` in the `push_jmp_target` branch before checking `if (! Trampoline)`. The same failure path freed `context` with `ExFreePoolWithTag(context, tzuk)` and then restored `*pSourceFunc = context->SaveBytesAddr`. Microsoft documents `ExAllocatePoolWithTag` as returning `NULL` on insufficient pool memory and `ExFreePool` as releasing pool memory that must not be accessed after it is freed; the same page points `ExAllocatePoolWithTag` buffers to `ExFreePoolWithTag`. |
| Data | `Gui_HookService`, `pSourceFunc`, `OriginalSourceFunc`, `pJumpStub`, `TargetFunc`, `GUI_HOOKSERVICE_CONTEXT`, `SaveBytesAddr`, `Trampoline`, `Hook_BuildTramp`, `push_jmp_target`, `Hook_BuildJump`, `Process_BuildHookEntry`, `Gui_HookFreeze`, `ExFreePoolWithTag`, and `STATUS_UNSUCCESSFUL`. |
| Schema | `GUI_XP_HOOK_TRAMPOLINE_FAILURE_LIFETIME` says `Gui_HookService` stores the original source function pointer in owner-local storage before any failure edge can free the hook context; `GUI_HOOKSERVICE_CONTEXT::SaveBytesAddr` mirrors the original source function pointer but is not the failure-restore owner after context cleanup; `Hook_BuildTramp` may return `NULL` when instruction analysis or trampoline allocation/copy fails; `Gui_HookService` checks the `Hook_BuildTramp` result before SpySweeper push-jump trampoline writes through it; `push_jmp_target` special trampoline patching only runs after `Trampoline` is non-null; failure cleanup frees `GUI_HOOKSERVICE_CONTEXT` only before restoring `pSourceFunc` from `OriginalSourceFunc`; failure cleanup never dereferences `context` after `ExFreePoolWithTag(context, tzuk)`; successful hook topology and `Process_BuildHookEntry` behavior are unchanged; XP win32k service discovery, hotfix prolog handling, MDL locking, and DPC freeze topology are unchanged. |
| Topology | The successful path remains original service pointer snapshot, prolog analysis, `Hook_BuildTramp`, optional push-jump patch, `*pSourceFunc = Trampoline`, `Process_BuildHookEntry`, MDL writable mapping, DPC freeze, and `Hook_BuildJump`. The corrected failure path snapshots `OriginalSourceFunc`, lets any failure flow through freeze/thread cleanup and `ExFreePoolWithTag(context)`, then restores `*pJumpStub = 0` and `*pSourceFunc = OriginalSourceFunc` without reading freed context storage. |
| Logic Risk | Kernel hook installation is a state machine over executable pointers. A trampoline pointer is not legal until `Hook_BuildTramp` returns non-null; writing push/jump bytes before that gate can become a kernel NULL write on allocation or decode failure. `context->SaveBytesAddr` contains the right value, but after `ExFreePoolWithTag(context, tzuk)` the context no longer owns readable storage. The correct local repair is to preserve the original source pointer in a stack variable and restore from it after cleanup, not to change hook policy or trampoline construction. |
| Official Shape | `docs/plan/srev-128-gui-xp-hook-trampoline-failure-lifetime.md` records Microsoft `ExAllocatePoolWithTag` and `ExFreePool` references plus the local `Hook_BuildTramp` NULL-return shape. `docs/plan/srev-128-gui-xp-hook-trampoline-failure-lifetime.schema.json` records the JSON Schema draft-07 local `GUI_XP_HOOK_TRAMPOLINE_FAILURE_LIFETIME` contract. |
| Fix | `Gui_HookService` now captures `OriginalSourceFunc = *pSourceFunc` before allocating the context, initializes `context->SaveBytesAddr` from that snapshot, checks `Hook_BuildTramp` immediately before the `push_jmp_target` write block, and restores `*pSourceFunc = OriginalSourceFunc` on failure after `context` has been freed. No service discovery, hotfix prolog detection, trampoline construction policy, hook entry generation, MDL locking, DPC freeze, successful jump write, or retry topology changed. |
| Acceptance Gate | `docs/plan/check-srev-128.py` validates the draft-07 schema, official references, local `Hook_BuildTramp` NULL-return shape, original source pointer snapshot, immediate trampoline null gate before `push_jmp_target`, stale post-free `context->SaveBytesAddr` restore removal, unchanged successful hook topology, and ledger entry; `docs/plan/check-srev-128.sh` is the matrix wrapper. Runtime/build gate: Windows build for `gui_xp.c`, XP hook install smoke for all affected services, failure injection where `Hook_BuildTramp` returns `NULL` on a `push_jmp_target` prolog proving no NULL write and clean `FALSE` return, failure injection after `*pSourceFunc = Trampoline` proving restore to original pointer, and Driver Verifier or kernel debugger observation proving no freed context access. |
