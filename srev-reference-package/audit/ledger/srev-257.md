### SREV-257: Custom Avast Trampoline Publish Gate

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official FlushInstructionCache and local trampoline publication review; needs Windows Avast/SnxHk runtime proof |
| Evidence | The Avast/SnxHk compatibility hook intercepts `LdrGetProcedureAddress` for `ntdll!NtDeviceIoControlFile` and returns a generated executable trampoline instead of the Sandboxie-hooked native stub. Before this SREV, the code published the static `code` pointer before writing the trampoline bytes and returned it without an instruction-cache boundary. |
| Data | `Custom_Avast_SnxHk_LdrGetProcedureAddress`, `__sys_LdrGetProcedureAddress`, `Dll_Ntdll`, `NtDeviceIoControlFile`, `Dll_AllocCode128`, generated x86/x64 absolute-jump trampoline bytes, `FlushInstructionCache`, static `code`, and the returned `Address` output slot. |
| Schema | `CUSTOM_AVAST_TRAMPOLINE_PUBLISH_GATE` says the Avast compatibility path owns one generated executable trampoline for `ntdll!NtDeviceIoControlFile`; generated executable bytes must be written through a local unpublished pointer; the generated code range must be flushed before publication through static `code` or the returned `Address` output slot; allocation failure must return the native lookup status without writing through a null trampoline pointer; this SREV does not change hook selection, `LdrGetProcedureAddress` forwarding, target API name matching, or generated x86/x64 trampoline bytes. |
| Topology | `LdrGetProcedureAddress(ntdll, "NtDeviceIoControlFile") -> native lookup gives hooked address -> allocate executable code slot -> write absolute-jump trampoline through unpublished local pointer -> FlushInstructionCache(local pointer, generated byte span) -> publish static code pointer -> return published pointer through Address`. |
| Logic Risk | Publishing `code` before writing the bytes allows a racing call to observe a non-null static pointer whose executable contents are not complete. Returning a generated executable stub without flushing the instruction cache violates the same execution boundary already recorded by SREV-058 and SREV-247. |
| Official Shape | `docs/plan/srev-257-custom-avast-trampoline-publish-gate.md` records Microsoft `FlushInstructionCache` and `VirtualAlloc` references. `docs/plan/srev-257-custom-avast-trampoline-publish-gate.schema.json` records the JSON Schema draft-07 local `CUSTOM_AVAST_TRAMPOLINE_PUBLISH_GATE` contract. |
| Fix | The code now writes through a local `new_code` pointer, gates null allocation, flushes the generated 12-byte range, and only then assigns `code = new_code`. The returned trampoline byte sequence and target matching are unchanged. |
| Acceptance Gate | `docs/plan/check-srev-257.py` validates the draft-07 schema, official reference links, local unpublished-pointer write, allocation gate, flush before static publication, unchanged target matching and trampoline byte sequence, SREV-058/SREV-247 adjacency, and the ledger fragment; `docs/plan/check-srev-257.sh` is the targeted wrapper. Runtime/build gate: Windows x86/x64 with Avast/SnxHk compatibility smoke proving the generated `NtDeviceIoControlFile` trampoline is returned and callable, with no stale-code execution or hook-copy crash. |
