### SREV-327: Secure AppInfo Binding Handle Layout Probe

| Field | Content |
|---|---|
| Severity | [medium] |
| Status | patched source-level official RPC binding object UUID query; needs Windows runtime proof |
| Evidence | `Secure_CheckElevation` detects UAC elevation calls by validating `RPC_ASYNC_STATE`, `RpcNotificationTypeEvent`, and `AsyncState->u.hEvent`. It now queries `Args->BindingHandle` with `RpcBindingInqObject` and compares the returned object UUID to the known AppInfo elevation UUIDs. If the RPC runtime does not classify the value as a binding, it falls back to the observed AppInfo layout probe: cast `Args->BindingHandle` to `UCHAR *`, keep the small-handle guard, and read the GUID at `OFFSET_OF_BINDING_GUID` through `memcmp`. |
| Data | `Secure_CheckElevation`, `Secure_IsElevationBindingGuid`, `RpcBindingInqObject`, `SECURE_UAC_ARGS`, `RPC_ASYNC_STATE`, `RpcNotificationTypeEvent`, `AsyncState->u.hEvent`, `BindingHandle`, `SIZEOF_RPC_ASYNC_STATE`, `OFFSET_OF_BINDING_GUID`, `elevation_binding_1`, `elevation_binding_2_Vista`, `elevation_binding_2_Win7`, fallback `ptr < (UCHAR*)0x1fff`, `IS_BINDING_GUID`, `Secure_Elevation_Type`, and `Secure_Elevation_ResultHandle`. |
| Schema | `SECURE_APPINFO_BINDING_HANDLE_LAYOUT_PROBE` says official RPC binding handles are opaque RPC runtime objects, not structures Sandboxie may parse by contract; `RpcBindingInqObject` is the supported first route for reading an object UUID from a binding handle; `RPC_ASYNC_STATE` owns only the documented async state and notification shape; `Secure_CheckElevation` uses `RpcBindingInqObject` first and the local observed AppInfo binding layout probe only as a compatibility fallback; fallback layout probing must keep the small-handle guard before any fixed-offset GUID read; `OFFSET_OF_BINDING_GUID` values are local evidence, not official Microsoft binding-handle ABI; runtime proof must classify `BindingHandle` and record whether the official object UUID query or fallback layout probe matched before changing offsets, guards, GUID comparison, or `__try` exception behavior. |
| Topology | `NdrAsyncClientCall stack -> RpcRt_NdrAsyncClientCall / Secure_CheckElevation handoff -> Secure_CheckElevation -> RPC_ASYNC_STATE shape gate -> RpcBindingInqObject official object UUID query -> if invalid binding: local pointer/small-handle gate -> fallback fixed-offset binding GUID probe -> elevation type/result handle capture`. |
| Logic Risk | Official RPC docs say binding handles are runtime-owned and applications cannot directly access the binding-handle data structure. The source now asks the RPC runtime for the object UUID first. The fallback `ptr < 0x1fff` guard avoids obvious small real handles, but it does not prove the remaining value is a safe, readable binding layout. Because the code is inside `__try`, invalid fallback reads are caught, but that does not make the fixed-offset fallback a documented contract. |
| Official Shape | `docs/plan/srev-327-secure-appinfo-binding-handle-layout-probe.md` records Microsoft binding-handle, `RPC_BINDING_HANDLE`, `RpcBindingFromStringBinding`, `RpcBindingInqObject`, `RPC_ASYNC_STATE`, and `RPC_NOTIFICATION_TYPES` references. `docs/plan/srev-327-secure-appinfo-binding-handle-layout-probe.schema.json` records the JSON Schema draft-07 local `SECURE_APPINFO_BINDING_HANDLE_LAYOUT_PROBE` contract. |
| Runtime Capture Matrix | Windows 10/11 build number, x64/WOW64 process shape, type-1 process elevation, type-2 token elevation, `RPC_ASYNC_STATE.Size`, `NotificationType`, `u.hEvent`, `RpcNotificationTypeEvent` acceptance, null/small/readable/unreadable/RPC-handle-like `BindingHandle` value class, `RpcBindingInqObject` status, returned object UUID, official object UUID match/miss, fallback `OFFSET_OF_BINDING_GUID`, fallback GUID match/miss, `__try` exception code, fallback guard-before-`memcmp` proof, elevation type, result handle slot, process image, AppInfo call identity, final broker result, and negative controls for non-AppInfo async RPC, non-event notification, missing event, small handle-like value, mismatched GUID, unreadable pointer, and ordinary non-elevation RPC. |
| Shared Runtime Capture Evidence | Runtime records use `docs/plan/srev-326-327-secure-runtime-capture.schema.json`; `docs/plan/srev-326-327-secure-runtime-capture-playbook.md` is the capture procedure; `docs/plan/check-srev-326-327-secure-runtime-capture.sh` validates the shared secure evidence contract. |
| Fix | Source-level official API first path. `Secure_CheckElevation` now calls `RpcBindingInqObject` to query the binding-handle object UUID before using the observed AppInfo memory-layout probe. If `RpcBindingInqObject` succeeds, its object UUID result decides the binding match. If it fails or is unavailable, the old fixed-offset memory probe remains as a compatibility fallback with the small-handle guard kept before the `memcmp`. No async-state predicate, notification gate, GUID byte offset, elevation type detection, output handle capture, exception handling, or service request behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-327.py` validates the draft-07 schema, official references, `RpcBindingInqObject` official object UUID query, preserved async-state gates, preserved 32/64-bit binding GUID offsets, fallback small-handle guard before fallback `memcmp`, preserved type-1/type-2 elevation detection, stale hack wording removal, combined ledger entry, split ledger fragment, and concrete runtime capture matrix; `docs/plan/check-srev-327.sh` is the targeted wrapper. `docs/plan/check-srev-326-327-secure-runtime-capture.sh` validates the shared secure runtime playbook and machine-readable evidence schema `docs/plan/srev-326-327-secure-runtime-capture.schema.json`. Windows gate: capture AppInfo UAC elevation calls on supported Windows 10/11 builds and x64/WOW64 where supported, then prove `RpcBindingInqObject` status, object UUID result, fallback `BindingHandle` value class, async-state fields, fallback guard result, fallback GUID probe result, `__try` exception path, elevation type, result handle slot, process image, AppInfo call identity, and negative controls before release. |
