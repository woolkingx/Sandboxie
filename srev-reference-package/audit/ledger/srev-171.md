### SREV-171: Object Name Helper Pipe Routing

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official `NtQueryObject`, file-handle type, and file-device information review; needs Windows named-pipe runtime proof |
| Evidence | `Sandboxie/core/dll/obj.c` was the highest-ranked unnamed reviewable core file after SREV-170. KPATH-003 already documented that native `NtQueryObject(ObjectNameInformation)` can hang on synchronous pipe handles with pending I/O and patched the external `Obj_NtQueryObject` hook to classify named-pipe File handles before native object-name query. The internal `Obj_GetObjectName` helper carried the same hang-risk comment but still used native object-name query whenever `UseDriverObjLookup` was disabled. Internal callers in `file.c`, `key.c`, `ipc.c`, and `secure.c` use this helper for root or arbitrary object handles, so the helper remained a second route into the same pipe-name hang class. |
| Data | `Sandboxie/core/dll/obj.c`, `Sandboxie/core/dll/obj.h`, `Sandboxie/core/dll/file_dir.c`, `Obj_GetObjectName`, `Obj_NtQueryObject`, `Obj_GetObjectType`, `Obj_IsNamedPipeFileHandle`, `Obj_GetObjectNameFromDriver`, `NtQueryObject`, `ObjectNameInformation`, `ObjectTypeInformation`, `NtQueryVolumeInformationFile`, `FileFsDeviceInformation`, `FILE_FS_DEVICE_INFORMATION`, `FILE_DEVICE_NAMED_PIPE`, `UseDriverObjLookup`, and `SbieApi_GetFileName`. |
| Schema | `OBJ_HELPER_PIPE_NAME_ROUTING` says `obj.c` owns both the hooked `Obj_NtQueryObject` route and the internal `Obj_GetObjectName` helper route; native `NtQueryObject(ObjectTypeInformation)` may classify the Object Manager object type, but native `NtQueryObject(ObjectNameInformation)` is not the owner of pipe/file identity; File handles that may be named pipes are classified through `NtQueryVolumeInformationFile(FileFsDeviceInformation)` and `FILE_FS_DEVICE_INFORMATION.DeviceType`; `DeviceType == FILE_DEVICE_NAMED_PIPE` routes name lookup through `Obj_GetObjectNameFromDriver`; `UseDriverObjLookup` remains the broader setting that routes all helper lookups through the driver; driver-routed named-pipe lookups must not fall back to native object-name query; Linux source gates are not Windows named-pipe hang reproduction or compatibility proof. |
| Topology | `Obj_GetObjectName` now flows through `UseDriverObjLookup` or, for File objects, `Obj_IsNamedPipeFileHandle`; named-pipe File handles use `Obj_GetObjectNameFromDriver`; non-pipe and non-File helper lookups keep native `NtQueryObject(ObjectNameInformation)`. `Obj_NtQueryObject` keeps the KPATH-003 topology: classify supported types, route File handles through driver lookup when `UseDriverObjLookup` or named-pipe device classification says so, avoid native fallback for driver-routed failures, and then rewrite file/key/ipc names on successful name query. |
| Logic Risk | The external hook route and internal helper route crossed the same unsafe boundary but only one had the default-on pipe classification. A sandboxed path construction or security path that calls `Obj_GetObjectName` with a pipe-backed File handle could still block on native object-name query after KPATH-003 closed the public hook route. |
| Official Shape | `docs/plan/srev-171-obj-helper-pipe-name-routing.md` records Microsoft `NtQueryObject`, `GetFileType`, `NtQueryVolumeInformationFile`, `FILE_FS_DEVICE_INFORMATION`, and device-type references. `docs/plan/srev-171-obj-helper-pipe-name-routing.schema.json` records the JSON Schema draft-07 local `OBJ_HELPER_PIPE_NAME_ROUTING` contract. |
| Fix | `Obj_GetObjectName` now calls `Obj_GetObjectNameFromDriver` when `UseDriverObjLookup` is enabled or when `Obj_GetObjectType(ObjectHandle) == OBJ_TYPE_FILE` and `Obj_IsNamedPipeFileHandle(ObjectHandle)` reports `FILE_DEVICE_NAMED_PIPE`. Non-pipe helper lookups still use native `NtQueryObject(ObjectNameInformation)`. No driver API wire shape, object-type classification table, file/key/ipc path rewrite code, or caller buffer copy contract changed. |
| Acceptance Gate | `docs/plan/check-srev-171.py` validates the draft-07 schema, official references, `obj.h` helper owner surface, `obj.c` native function capture, named-pipe device classification, helper-level driver routing, existing KPATH-003 hook routing, no helper regression to the old `UseDriverObjLookup`-only gate, `file_dir.c` named-pipe precedent, and ledger fragment; `docs/plan/check-srev-171.sh` is the matrix wrapper. Runtime gate: Windows build plus a sandboxed named-pipe repro where a synchronous pipe handle with a pending read is passed through both `NtQueryObject(ObjectNameInformation)` and an internal helper path such as root-handle path construction; neither route may hang, normal file/key/ipc name rewriting must still work, and failed driver-routed pipe lookups must not fall back to native object-name query. |
