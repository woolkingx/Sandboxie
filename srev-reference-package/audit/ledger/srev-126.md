### SREV-126: GUI Enum Window Station Handle Ownership

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official window-station get/create/close and handle-duplication shape; needs Windows GUI runtime proof |
| Evidence | `Sandboxie/core/dll/guienum.c` was the highest-ranked unnamed reviewable core file after SREV-125. `Gui_CreateWindowStationW` and `Gui_CreateWindowStationA` first call the native `CreateWindowStationW/A`; if that fails, selected browser / `UseSbieWndStation` fallback paths returned `Gui_Dummy_WinSta`. That dummy handle is captured in `Sandboxie/core/dll/gui.c` from `GetProcessWindowStation()` and then set as the process window station. Microsoft documents `GetProcessWindowStation` as returning the current process window-station handle and explicitly says not to close that handle. Microsoft documents `CreateWindowStationW` as returning a handle that must be freed with `CloseWindowStation`, and `CloseWindowStation` says its input should be a handle returned by `CreateWindowStation` or `OpenWindowStation`, not `GetProcessWindowStation`. Microsoft documents `DuplicateHandle` as producing a duplicate handle value valid in the target process, including window-station handles returned by `GetProcessWindowStation`, with a nonzero return on success. |
| Data | `Gui_CreateWindowStationW`, `Gui_CreateWindowStationA`, `Gui_Dummy_WinSta`, `GetProcessWindowStation`, `CreateWindowStationW`, `CreateWindowStationA`, `CloseWindowStation`, `DuplicateHandle`, `GetCurrentProcess`, `SECURITY_ATTRIBUTES.bInheritHandle`, `DUPLICATE_SAME_ACCESS`, `UseSbieWndStation`, `DLL_IMAGE_GOOGLE_CHROME`, `DLL_IMAGE_MOZILLA_FIREFOX`, and `SbieApi_Log(2205, L"CreateWindowStation")`. |
| Schema | `GUIENUM_WINDOWSTATION_HANDLE_OWNERSHIP` says `Gui_Dummy_WinSta` is a process window-station handle captured from the process window-station topology; `GetProcessWindowStation` returned handles are process-owned and must not be closed by ordinary callers; `CreateWindowStationW/A` returned handles are caller-owned and releasable with `CloseWindowStation`; the fallback must not return `Gui_Dummy_WinSta` directly; when fallback uses `Gui_Dummy_WinSta`, it returns a duplicate handle produced by `DuplicateHandle` in the current process with `DUPLICATE_SAME_ACCESS`; duplicate inheritability follows `SECURITY_ATTRIBUTES.bInheritHandle` when `lpsa` is supplied; native `CreateWindowStationW/A`, fallback policy predicates, logging, and failure return shape are unchanged. |
| Topology | The native path remains `Gui_CreateWindowStationW/A` to `__sys_CreateWindowStationW/A(...)` and direct native handle return on success. The fallback path is now `Gui_Dummy_WinSta` policy gate, derive inheritability from `lpsa`, duplicate `Gui_Dummy_WinSta` into the current process with `DuplicateHandle`, and return the duplicate as the caller-owned fallback handle. Duplicate failure flows to the existing log-and-zero failure path. |
| Logic Risk | The old fallback crossed incompatible handle ownership schemas. A `GetProcessWindowStation` handle is process-associated state and must not be closed, but a `CreateWindowStation` return value is caller-owned and expected to be closed with `CloseWindowStation`. Returning the dummy handle directly let a normal caller follow the public API contract and close or attempt to close Sandboxie's process window-station state. The correct repair is a duplicate at the fallback boundary, not a change to the policy deciding when fallback is used. |
| Official Shape | `docs/plan/srev-126-guienum-windowstation-handle-ownership.md` records Microsoft `GetProcessWindowStation`, `CreateWindowStationW`, `CloseWindowStation`, and `DuplicateHandle` references. `docs/plan/srev-126-guienum-windowstation-handle-ownership.schema.json` records the JSON Schema draft-07 local `GUIENUM_WINDOWSTATION_HANDLE_OWNERSHIP` contract. |
| Fix | `Gui_CreateWindowStationW` and `Gui_CreateWindowStationA` now duplicate `Gui_Dummy_WinSta` with `DuplicateHandle(GetCurrentProcess(), Gui_Dummy_WinSta, GetCurrentProcess(), &hDuplicate, 0, inherit, DUPLICATE_SAME_ACCESS)` before returning it from fallback. `inherit` is derived from `lpsa->bInheritHandle` when `lpsa` exists. If duplication fails, the functions keep the existing `SbieApi_Log(2205, L"CreateWindowStation")` and `return 0` failure path. No native `CreateWindowStationW/A` call, fallback predicate, browser exception, log message, or non-fallback behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-126.py` validates the draft-07 schema, official references, `Gui_Dummy_WinSta` source topology, duplicate-handle fallback in both W/A paths, inheritability preservation from `SECURITY_ATTRIBUTES`, stale direct `return Gui_Dummy_WinSta` removal, native direct-return preservation, fallback policy preservation, and ledger entry; `docs/plan/check-srev-126.sh` is the matrix wrapper. Runtime/build gate: Windows GUI build for `guienum.c`, fallback smoke proving returned handle is a duplicate and `CloseWindowStation` on it does not close `Gui_Dummy_WinSta`, inheritability matrix for null/false/true `lpsa`, native success smoke proving unchanged direct return, and duplicate failure injection proving log-and-zero failure behavior. |
