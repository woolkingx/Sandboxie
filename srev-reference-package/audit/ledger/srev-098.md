### SREV-098: IE Embedding CLSID Registry Policy

| Field | Content |
|---|---|
| Severity | [minor] |
| Status | source-level classified after official registry-filter callback, REG_NOTIFY_CLASS, COM CLSID registration, LocalServer32/InprocServer32, and IWebBrowser2 shape; comment-only source clarification, no behavior change |
| Evidence | `Sandboxie/core/drv/key_flt.c` registers a Vista+ registry callback through `CmRegisterCallbackEx`, handles only `RegNtPreCreateKeyEx` and `RegNtPreOpenKeyEx` for ordinary create/open routing, then conditionally denies opens/creates whose `CompleteName` contains `CLSID\\{0002df01-0000-0000-c000-000000000046}` when `BlockIEEmbedding` is enabled and the caller is a selected host process. Microsoft documents registry callbacks as able to block a pre-notification by returning a non-success `NTSTATUS`. Microsoft documents COM class registration as CLSID registry data used to create class instances, `LocalServer32` as a local-server executable path where COM appends `-Embedding`, and `IWebBrowser2` as implemented by the WebBrowser ActiveX control or an InternetExplorer application instance. Local `comserver9_ie.c` defines this GUID as `CLSID_InternetExplorer`, and `comserver9.c` registers Sandboxie's IE COM server for that CLSID. |
| Data | `BlockIEEmbedding`, `RegNtPreCreateKeyEx`, `RegNtPreOpenKeyEx`, `CompleteName`, InternetExplorer CLSID `{0002DF01-0000-0000-C000-000000000046}`, selected host callers `winword.exe` / `powerpnt.exe` / `excel.exe` / `explorer.exe` / `svchost.exe`, `STATUS_ACCESS_DENIED`, and ordinary `Key_MyParseProc_2` sandbox key redirection. |
| Schema | `IE_EMBEDDING_CLSID_REGISTRY_POLICY` says `Key_Callback` handles only create/open pre-notifications for this policy; `BlockIEEmbedding` is a registry lookup denial policy, not a process launch owner; the denied key is the local InternetExplorer CLSID; the policy applies only to selected host callers where `proc` is `NULL`; the selected callers are `winword.exe`, `powerpnt.exe`, `excel.exe`, `explorer.exe`, and `svchost.exe`; the policy returns `STATUS_ACCESS_DENIED` before ordinary sandbox key redirection; `SearchUnicodeString` is the `CompleteName` matcher and remains null-safe; normal sandboxed registry redirection remains owned by `Key_MyParseProc_2`. |
| Topology | `CmRegisterCallbackEx` installs `Key_Callback`. For create/open pre-notifications, the callback checks the IE CLSID in `CompleteName`, checks `BlockIEEmbedding`, gets the current process name, requires the host-side `!proc` boundary, and returns `STATUS_ACCESS_DENIED` for selected host callers. If the policy does not deny, host callers pass through and sandboxed callers continue to `Key_MyParseProc_2`. |
| Logic Risk | The old `HACK ALERT` comment made the block look like a generic ForceProcess workaround. The official shape says it is narrower: a registry pre-notification denial that prevents COM from resolving one embedded IE CLSID path. Broadening caller scope or changing COM activation behavior from this source alone would be wrong; that requires a Windows Office/IE runtime matrix. |
| Official Shape | `docs/plan/srev-098-ie-embedding-clsid-registry-policy.md` records Microsoft registry callback registration, notification handling, `REG_NOTIFY_CLASS`, `REG_CREATE_KEY_INFORMATION_V1`, COM server registration, `LocalServer32`, `InprocServer32`, and `IWebBrowser2` references. `docs/plan/srev-098-ie-embedding-clsid-registry-policy.schema.json` records the JSON Schema draft-07 local `IE_EMBEDDING_CLSID_REGISTRY_POLICY` contract. |
| Fix | Comment-only source clarification: the stale `HACK ALERT` wording was replaced with a `BlockIEEmbedding` policy-boundary comment stating that the driver hides the InternetExplorer COM class from selected host callers so COM activation cannot start an embedded IE server path that bypasses Sandboxie's process-launch forcing. No runtime behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-098.py` validates the draft-07 schema, official references, registry callback registration, create/open pre-notification scope, InternetExplorer CLSID local identity, `BlockIEEmbedding` gate, selected host caller list, `STATUS_ACCESS_DENIED` before ordinary sandbox redirection, null-safe `SearchUnicodeString`, stale `HACK ALERT` removal, and ledger entry; `docs/plan/check-srev-098.sh` is the matrix wrapper. Runtime gate: Windows matrix with Word, PowerPoint, Excel, Explorer, and Svchost host callers; `BlockIEEmbedding` on/off; Office hyperlink open; COM activation trace for CLSID `{0002DF01-0000-0000-C000-000000000046}`; and ForceProcess observation for the resulting normal IE process path. |
