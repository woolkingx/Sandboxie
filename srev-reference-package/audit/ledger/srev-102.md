### SREV-102: Syscall64 Private Table Scanner Boundary

| Field | Content |
|---|---|
| Severity | [minor] |
| Status | source-level classified after official Microsoft KVA Shadow / KB4056892, Intel Rogue Data Cache Load, Windows ARM64 ABI, and ARM64 WDK shape; comment-only source clarification, no behavior change |
| Evidence | `Sandboxie/core/drv/syscall_64.c` discovers 64-bit service tables by using the exported `KeServiceDescriptorTable` when available, otherwise scanning `KeAddSystemServiceTable` private instruction patterns. The uncovered Meltdown comment sat above a disabled x64 `0x40` / `0xC0` table-spacing check. Microsoft documents KVA Shadow as the Windows mitigation for CVE-2017-5754 / Meltdown, says it changes x64 trap and system-service dispatch internals, and warns drivers must not depend on those internals without updated documentation. The uncovered ARM64 `TODO` sat in the filter-table scanner branch, which currently returns `0` and lets `Syscall_GetServiceTableFilter` fail closed. |
| Data | `Syscall_GetMasterServiceTable`, `KeServiceDescriptorTable`, `KeAddSystemServiceTable`, disabled x64 spacing check, `MasterTable`, `ShadowTable`, `ShadowTable->Addrs`, `Dyndata_Config.ServiceTable_offset`, ARM64 `ADRP` / `ADD` master-table scanner, ARM64 `KeServiceDescriptorTableFilter` lookup branch, and `Syscall_GetServiceTableFilter` fail-closed path. |
| Schema | `SYSCALL64_PRIVATE_TABLE_SCANNER_BOUNDARY` says `Syscall_GetMasterServiceTable` uses exported `KeServiceDescriptorTable` when available before private pattern scanning; the disabled x64 `0x40` / `0xC0` spacing check is a historical private invariant and must not be re-enabled from source comments alone; KVA Shadow / KB4056892 changed x64 kernel-entry and system-service dispatch internals for Meltdown mitigation; Microsoft says those details are subject to change; `Syscall_GetServiceTable` still validates `ShadowTable->Addrs` against `MasterTable->Addrs`; ARM64 filter-table lookup remains fail-closed until a version-gated pattern is proven; this SREV does not change service table offsets, scanner behavior, or dispatch. |
| Topology | x64 path: `MmGetSystemRoutineAddress("KeServiceDescriptorTable")` -> exported table if present -> otherwise scan `KeAddSystemServiceTable` -> derive `MasterTable` -> derive `ShadowTable` by OS-build offsets -> require matching `Addrs`. ARM64 path: master-table lookup scans `KeAddSystemServiceTable` for `ADRP` / `ADD`; filter-table lookup is intentionally fail-closed today and logs `FILTER TABLE` through the caller. |
| Logic Risk | The old `broken` wording invited the wrong repair: re-enable or reshape a private kernel invariant after a mitigation specifically changed kernel-entry internals. The official boundary is weaker: runtime-version-gated scanner evidence is required. The old ARM64 `TODO` similarly invited x64-pattern analogy into ARM64 without Windows ARM64 runtime evidence. |
| Official Shape | `docs/plan/srev-102-syscall64-private-table-scanner-boundary.md` records Microsoft KVA Shadow, KB4072698 / KB4056892 speculative-execution guidance, Intel Rogue Data Cache Load, Windows ARM64 ABI, and ARM64 WDK references. `docs/plan/srev-102-syscall64-private-table-scanner-boundary.schema.json` records the JSON Schema draft-07 local `SYSCALL64_PRIVATE_TABLE_SCANNER_BOUNDARY` contract. |
| Fix | Comment-only source clarification: the disabled spacing check now says KVA Shadow / KB4056892 changed x64 kernel-entry layout enough that the private invariant is not legal; the ARM64 filter-table placeholder now says lookup remains fail-closed until a version-gated `KeAddSystemServiceTable` pattern is proven on real Windows ARM64 builds. No behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-102.py` validates the draft-07 schema, official references, export-first table lookup, disabled spacing-check shape, post-derivation `ShadowTable->Addrs` validation, ARM64 master-table `ADRP` / `ADD` pattern, ARM64 filter-table fail-closed wording, stale `broken` and `TODO` wording removal from `syscall_64.c`, and ledger entry; `docs/plan/check-srev-102.sh` is the matrix wrapper. Runtime gate: Windows x64/ARM64 matrix with Windows 7 x64 pre/post KB4056892, Windows 10/11 x64 with KVA Shadow on/off where applicable, Windows ARM64 supported WDK builds, service table discovery, filter table discovery, Driver Verifier, HVCI on/off, and syscall dispatch smoke for ordinary NT and win32k syscall entries. |
