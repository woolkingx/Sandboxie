### SREV-184: XP File Open Packet Offset Contract

| Field | Content |
|---|---|
| Severity | [minor] |
| Status | patched source-level after official `FIELD_OFFSET` and `ACCESS_STATE` review; needs Windows XP driver build and runtime proof |
| Evidence | `Sandboxie/core/drv/file_xp.c` was the highest-ranked unnamed reviewable core file after SREV-183. It owns the 32-bit Windows XP/2003 file and device parse-procedure hook. `File_CreateMyContext` casts the parse `Context` to private local `OPEN_PACKET` after checking `Type == IO_TYPE_OPEN_PACKET`, then reads `CreateOptions`, `Options`, and `CreateDisposition` into the shared `MY_CONTEXT` consumed by `File_Generic_MyParseProc`. The old source comments named private offsets `0x20`, `0x30`, and `0x34`, but no source gate proved that the local struct still matched those offsets. The same comment also described Vista/7/8 layout compatibility even though `file.c` dispatches this hook only when `Driver_OsVersion < DRIVER_WINDOWS_VISTA`; Vista+ uses the minifilter path. |
| Data | `Sandboxie/core/drv/file_xp.c`, `Sandboxie/core/drv/file.c`, `Sandboxie/core/drv/obj.h`, `OPEN_PACKET`, `File_CreateMyContext`, `File_File_MyParseProc`, `File_Device_MyParseProc`, `File_Generic_MyParseProc`, `OBJ_PARSE_PROC_ARGS`, `OBJ_CALL_SYSTEM_PARSE_PROC`, `FIELD_OFFSET`, `ACCESS_STATE.OriginalDesiredAccess`, `IO_OPEN_TARGET_DIRECTORY`, `File_Init_XpHook`, `File_Unload_XpHook`, and `File_Init_Filter`. |
| Schema | `XP_FILE_OPEN_PACKET_OFFSET_CONTRACT` says `file_xp.c` owns the 32-bit Windows XP/2003 file and device parse-procedure hook; `OPEN_PACKET` is a private local layout mirror used only by the XP parse-procedure path; `File_CreateMyContext` may read `CreateOptions`, `Options`, and `CreateDisposition` only after `Context->Type == IO_TYPE_OPEN_PACKET`; expected offsets are `CreateOptions == 0x20`, `Options == 0x30`, and `CreateDisposition == 0x34`; offsets are compile-time gates through `FIELD_OFFSET`; Vista and later use the minifilter route, so the XP parse hook must not claim Vista/7/8 context layout compatibility; `ACCESS_STATE.OriginalDesiredAccess` is read as original requested access and is not modified; file/device parse-procedure routing, policy decisions, `IO_OPEN_TARGET_DIRECTORY` handling, font token handling, and minifilter behavior must not change. |
| Topology | XP route: `File_Init` selects `File_Init_XpHook` when `Driver_OsVersion < DRIVER_WINDOWS_VISTA`, hooks object parse procedures for `File` and `Device`, maps parse context through `File_CreateMyContext`, calls `File_Generic_MyParseProc`, then returns through `OBJ_CALL_SYSTEM_PARSE_PROC`. Vista+ route: `File_Init` uses `File_Init_Filter`, so `file_flt.c` supplies the create/open context path into `File_Generic_MyParseProc`. |
| Logic Risk | Private kernel structure mirrors become dangerous when the code states offset assumptions only in comments. A future field edit, packing change, or mistaken reuse can silently move `CreateOptions`, `Options`, or `CreateDisposition`, causing file policy logic to consume the wrong bits. Mislabeling the hook as Vista/7/8 compatible also weakens the topology boundary between XP parse hooks and Vista+ minifilter callbacks. |
| Official Shape | `docs/plan/srev-184-xp-file-open-packet-offset-contract.md` records Microsoft `FIELD_OFFSET` and `ACCESS_STATE` references. `docs/plan/srev-184-xp-file-open-packet-offset-contract.schema.json` records the JSON Schema draft-07 local `XP_FILE_OPEN_PACKET_OFFSET_CONTRACT` contract. |
| Fix | `file_xp.c` now has compile-time `FIELD_OFFSET` gates for `OPEN_PACKET.CreateOptions == 0x20`, `OPEN_PACKET.Options == 0x30`, and `OPEN_PACKET.CreateDisposition == 0x34`. The stale Vista/7/8 comment now states the actual XP/2003 owner boundary and notes that Vista+ uses the minifilter path. No parse-procedure routing, file policy, device filtering, font token handling, `IO_OPEN_TARGET_DIRECTORY` exception, or minifilter behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-184.py` validates the draft-07 schema, official references, XP/minifilter dispatch topology, parse-procedure macro shape, compile-time `OPEN_PACKET` offset gates, guarded `IO_TYPE_OPEN_PACKET` reads, `ACCESS_STATE.OriginalDesiredAccess` readback, stale Vista/7/8 layout claim removal, and ledger fragment; `docs/plan/check-srev-184.sh` is the matrix wrapper. Runtime gate: Windows XP/2003 32-bit driver build with `XP_SUPPORT`, XP file and device parse-procedure hook smoke, file open and rename smoke proving `IO_OPEN_TARGET_DIRECTORY` handling is unchanged, and Vista+ minifilter smoke proving this legacy file is not active. |
