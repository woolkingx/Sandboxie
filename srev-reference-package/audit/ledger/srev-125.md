### SREV-125: File Copy Junction Handle State

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official native file-create, file-query, file-system-control, reparse-point, and handle-close shape; needs Windows junction migration runtime proof |
| Evidence | `Sandboxie/core/dll/file_copy.c` was the highest-ranked unnamed reviewable core file after SREV-124. `File_MigrateJunction` opens a source reparse point with `NtCreateFile`, queries `FILE_NETWORK_OPEN_INFORMATION`, reads the source reparse data with `FSCTL_GET_REPARSE_POINT`, creates a destination directory reparse point, sets the reparse data with `FSCTL_SET_REPARSE_POINT`, and then copies timestamps/attributes from `open_info`. The old source did not check the metadata query before later consuming `open_info`, returned directly after `FSCTL_GET_REPARSE_POINT` failure without closing `TrueHandle`, and after destination `NtCreateFile` failure closed/free'd local resources but fell through into `FSCTL_SET_REPARSE_POINT` with an invalid `CopyHandle`. Microsoft documents `NtCreateFile` as returning a file/directory handle that must later be closed, `NtQueryInformationFile` as returning `FILE_NETWORK_OPEN_INFORMATION` only through the caller buffer on success, `NtFsControlFile` as sending an FSCTL to a specified file handle, `FSCTL_SET_REPARSE_POINT` as requiring a non-null file handle and input buffer, and `FSCTL_GET_REPARSE_POINT` as returning status plus reparse data on successful completion. |
| Data | `File_MigrateJunction`, `TruePath`, `CopyPath`, `TrueHandle`, `CopyHandle`, `open_info`, `FILE_NETWORK_OPEN_INFORMATION`, `REPARSE_DATA_BUFFER`, `MAXIMUM_REPARSE_DATA_BUFFER_SIZE`, `FSCTL_GET_REPARSE_POINT`, `FSCTL_SET_REPARSE_POINT`, `NtCreateFile`, `NtQueryInformationFile`, `NtFsControlFile`, `NtClose`, `pSecurityDescriptor`, `File_AddCurrentUserToSD`, and `File_SetAttributes`. |
| Schema | `FILE_COPY_JUNCTION_HANDLE_STATE` says `File_MigrateJunction` opens the source reparse point before querying metadata or reparse data; `FILE_NETWORK_OPEN_INFORMATION` is used only after `NtQueryInformationFile(FileNetworkOpenInformation)` succeeds; source reparse data is used only after `FSCTL_GET_REPARSE_POINT` succeeds; every local failure after `TrueHandle` opens closes `TrueHandle` before returning; destination reparse data is set only after destination `NtCreateFile` succeeds and initializes `CopyHandle`; destination create failure frees copied security descriptor storage when one exists and returns before `FSCTL_SET_REPARSE_POINT`; reparse data shape, ACL copy policy, destination create options, and attribute-copy behavior are unchanged. |
| Topology | Successful junction migration flows from source `NtCreateFile(TruePath, FILE_OPEN_REPARSE_POINT)`, to `NtQueryInformationFile(TrueHandle, FileNetworkOpenInformation)`, to `NtFsControlFile(TrueHandle, FSCTL_GET_REPARSE_POINT)`, optional security descriptor copy, destination `NtCreateFile(CopyPath, FILE_CREATE | FILE_OPEN_REPARSE_POINT)`, `NtFsControlFile(CopyHandle, FSCTL_SET_REPARSE_POINT)`, `File_SetAttributes(CopyHandle, open_info)`, and final handle/security cleanup. Failure after source query, source get-reparse, or destination create now terminates at the owning cleanup edge instead of crossing into a later state. |
| Logic Risk | Native file and FSCTL calls publish handles or state only on success. Treating failed metadata query as if it had filled `open_info` can propagate uninitialized timestamps and attributes. Returning from a failed get-reparse call without closing `TrueHandle` leaks the source handle. Falling through after destination create failure is the largest edge error: it lets the set-reparse operation run against a destination handle that was never legally produced. The correct local repair is state gating and cleanup, not a change to junction migration policy or reparse-buffer semantics. |
| Official Shape | `docs/plan/srev-125-file-copy-junction-handle-state.md` records Microsoft `NtCreateFile`, `NtQueryInformationFile`, `NtFsControlFile`, `FSCTL_SET_REPARSE_POINT`, `FSCTL_GET_REPARSE_POINT`, and `ZwClose` / `NtClose` references. `docs/plan/srev-125-file-copy-junction-handle-state.schema.json` records the JSON Schema draft-07 local `FILE_COPY_JUNCTION_HANDLE_STATE` contract. |
| Fix | `File_MigrateJunction` now checks `NtQueryInformationFile` before any reparse-data work and closes `TrueHandle` on query failure. It also closes `TrueHandle` before returning on `FSCTL_GET_REPARSE_POINT` failure. Destination `NtCreateFile` failure now closes `TrueHandle`, frees `pSecurityDescriptor` when allocated, and returns immediately before any `FSCTL_SET_REPARSE_POINT` call. No source open access, `FILE_OPEN_REPARSE_POINT` usage, reparse buffer sizing, destination create flags, ACL copy policy, attribute copy, or successful cleanup path changed. |
| Acceptance Gate | `docs/plan/check-srev-125.py` validates the draft-07 schema, official references, metadata query gate before reparse get, source get-reparse failure cleanup, destination create failure return before set-reparse, stale handle-leak/fallthrough patterns removed, preserved source/destination reparse topology, and ledger entry; `docs/plan/check-srev-125.sh` is the matrix wrapper. Runtime/build gate: Windows build for `file_copy.c`, junction migration positive smoke, source `NtQueryInformationFile` failure injection proving `open_info` is not consumed and `TrueHandle` closes, source `FSCTL_GET_REPARSE_POINT` failure injection proving `TrueHandle` closes, destination `NtCreateFile` failure injection proving no `FSCTL_SET_REPARSE_POINT` with invalid `CopyHandle`, and security descriptor cleanup observation when allocated. |
