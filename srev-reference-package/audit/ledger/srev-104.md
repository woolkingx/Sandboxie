### SREV-104: Token SID Storage Copy Boundary

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official SID, `RtlValidSid`, `RtlLengthSid`, `RtlCopySid`, `SID_AND_ATTRIBUTES`, `TOKEN_USER`, `TOKEN_GROUPS`, `SeFilterToken`, and `SeQueryInformationToken` shape; needs Windows token SID storage runtime proof |
| Evidence | `Sandboxie/core/drv/token.c` `Token_RestrictHelper1` temporarily rewrites a filtered token's user SID through private `TOKEN.UserAndGroups` offsets before calling `SeFilterToken` again. The uncovered comments described Windows 8.1 shared SID storage and too-small system-process SID storage as workarounds. Microsoft documents `SID` as variable-length and says drivers must use support routines rather than editing SID fields directly; `RtlLengthSid` has undefined output for invalid SIDs and requires `RtlValidSid` first; `RtlCopySid` copies into a caller-allocated destination with an explicit byte length and returns `STATUS_BUFFER_TOO_SMALL` when the destination is too small. |
| Data | `Token_RestrictHelper1`, `TempNewTokenObject`, `Dyndata_Config.UserAndGroups_offset`, `SidAndAttrsInToken->Sid`, `Token_IsSharedSid_W8`, `proc->SandboxieLogonSid`, `AnonymousLogonSid`, `OrigTokenSid`, `RtlValidSid`, `RtlLengthSid`, `RtlCopySid`, `Sbie_SepFilterToken_KernelMode`, `Sbie_SeFilterToken_KernelMode`, and `ObDereferenceObject(TempNewTokenObject)`. |
| Schema | `TOKEN_SID_STORAGE_COPY_BOUNDARY` says SIDs are variable-length and must not be field-mutated directly; both the token SID and `SandboxieLogonSid` must pass `RtlValidSid` before `RtlLengthSid`; inline token SID rewrite uses `RtlCopySid` with the measured destination SID length; `Token_IsSharedSid_W8` is only a private offset-based classifier for whether inline copy is allowed; shared or too-small storage uses pointer substitution and restores the original pointer before the temporary token object is dereferenced; `TOKEN_USER` is not itself a `SeFilterToken` input, while `TOKEN_GROUPS` can carry a user SID as deny-only input. |
| Topology | `Token_RestrictHelper1` creates `TempNewTokenObject` with extra variable storage, finds `SidAndAttrsInToken` through `UserAndGroups_offset`, validates `SidInToken`, defaults `SandboxieLogonSid` to `AnonymousLogonSid` when configured, validates the replacement SID, measures both SID lengths, then either substitutes the SID pointer for shared/short storage or copies with `RtlCopySid(TokenSidLength, SidInToken, proc->SandboxieLogonSid)`. If pointer substitution was used, the original pointer is restored after `Sbie_SeFilterToken_KernelMode` and before `ObDereferenceObject(TempNewTokenObject)`. |
| Logic Risk | The old code only checked `SidInToken[1] >= 1`, then called `RtlLengthSid` on token and replacement SIDs and used raw `memcpy` for inline rewrite. That allowed private-offset drift or malformed replacement SID state to feed undefined SID length into a token object write. The corrected rule is data-shaped: valid SIDs first, measured capacity second, support-routine copy only when inline storage is legal and large enough. |
| Official Shape | `docs/plan/srev-104-token-sid-storage-copy-boundary.md` records Microsoft `SID`, `RtlValidSid`, `RtlLengthSid`, `RtlCopySid`, `SID_AND_ATTRIBUTES`, `TOKEN_USER`, `TOKEN_GROUPS`, `SeFilterToken`, and `SeQueryInformationToken` references. `docs/plan/srev-104-token-sid-storage-copy-boundary.schema.json` records the JSON Schema draft-07 local `TOKEN_SID_STORAGE_COPY_BOUNDARY` contract. |
| Fix | `Token_RestrictHelper1` now validates `SidInToken` and `proc->SandboxieLogonSid` with `RtlValidSid` before length calculation; stores both measured lengths once; keeps pointer substitution for `Token_IsSharedSid_W8` or insufficient inline destination bytes; and replaces raw inline `memcpy` with `RtlCopySid(TokenSidLength, SidInToken, proc->SandboxieLogonSid)`. The temporary token pointer restore, `SepFilterToken` / `SeFilterToken` call ordering, and restricted-SID cleanup topology are unchanged. |
| Acceptance Gate | `docs/plan/check-srev-104.py` validates the draft-07 schema, official references, SID validation before length calculation, `RtlCopySid` replacing the old inline `memcpy`, pointer substitution remaining only for shared or too-small storage, original pointer restore, stale uncovered workaround wording removal, and ledger entry; `docs/plan/check-srev-104.sh` is the matrix wrapper. Runtime gate: Windows token matrix covering Windows 7, Windows 8.1 before/after KB2919355, Windows 10, a configured SbieLogin SID longer than the original token SID, default AnonymousLogon, system-process token application, `Token_IsSharedSid_W8` true/false observations, Driver Verifier, and token object dereference/restore stability. |
