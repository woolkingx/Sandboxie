### SREV-119: Low Init Protect Write Gate

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official memory-protection, instruction-cache, and Nt/Zw native-service shape; needs Windows low-level bootstrap runtime proof |
| Evidence | `Sandboxie/core/low/init.c` was the highest-ranked unnamed reviewable core file after SREV-118. Its bootstrap path patches local low-level data, syscall export stubs, and ARM64 `LdrQueryImageFileExecutionOptionsEx` CHPE detours by first calling `NtProtectVirtualMemory(..., PAGE_EXECUTE_READWRITE, &OldProtect)`. The old source did not check the returned `NTSTATUS`; if the protection change failed, it still wrote through the target pointer and later restored with an uninitialized `OldProtect`. Microsoft documents the public `VirtualProtect` shape as changing protection on committed pages, failing without modifying protection when the requested region is invalid, and writing the old protection through an output pointer; Microsoft also documents that modified executable code requires instruction-cache coherency, and documents user-mode native-service calls as validated Nt/Zw system-service calls. |
| Data | `WriteMemorySafe`, `InitSyscalls`, `DisableCHPE`, `NtProtectVirtualMemory`, `NT_SUCCESS`, `PAGE_EXECUTE_READWRITE`, `OldProtect`, `RegionBase`, `RegionSize`, `SystemService`, `ZwXxxPtr`, `SyscallPtr`, `SyscallNum`, `RtlImageOptionsEx_tramp`, `RtlImageOptionsEx`, `NtFlushInstructionCache`, `NtDeviceIoControlFileEC`, and `EcExitThunkPtr`. |
| Schema | `LOW_INIT_PROTECT_WRITE_GATE` says `init.c` code or data patches that request `PAGE_EXECUTE_READWRITE` through `NtProtectVirtualMemory` must check `NTSTATUS` before writing; `OldProtect` is initialized before each writable-protection attempt; `OldProtect` is restored only after the writable-protection call succeeds; `WriteMemorySafe` fails closed when the protection change fails; `InitSyscalls` skips the current syscall export when the target stub cannot be made writable; `DisableCHPE` returns before trampoline or target-detour byte writes when the relevant region cannot be made writable; this SREV does not change syscall selection, detour bytes, ARM64EC wrapper routing, CHPE policy, or instruction-cache flush placement. |
| Topology | Early bootstrap data flows into local code/data patch sites. Each patch site first calls `NtProtectVirtualMemory` for `PAGE_EXECUTE_READWRITE`, checks `NT_SUCCESS(status)`, writes local bytes only after that gate, restores `OldProtect`, and keeps existing `NtFlushInstructionCache` calls for executable code patches. |
| Logic Risk | In low-level process bootstrap, an unchecked protection transition turns a failed precondition into a direct write through an address that may still be non-writable. That can crash the initializing process, skip cleanup, or leave waiting threads stuck behind the init lock. The correct local repair is a fail-closed protection gate, not a new policy decision about which syscall stubs, jump-table bytes, ARM64EC wrapper state, or CHPE behavior should exist. |
| Official Shape | `docs/plan/srev-119-low-init-protect-write-gate.md` records Microsoft `VirtualProtect`, `FlushInstructionCache`, and Nt/Zw native-service references. `docs/plan/srev-119-low-init-protect-write-gate.schema.json` records the JSON Schema draft-07 local `LOW_INIT_PROTECT_WRITE_GATE` contract. |
| Fix | `WriteMemorySafe`, `InitSyscalls`, and `DisableCHPE` now store the `NtProtectVirtualMemory` return value, initialize `OldProtect`, and write only after `NT_SUCCESS(status)`. `WriteMemorySafe` returns without writing on failure. `InitSyscalls` advances to the next syscall record when the current export cannot be made writable. `DisableCHPE` returns before copying trampoline or target detour bytes when the corresponding region cannot be made writable. No syscall-data layout, hook bytes, jump-table routing, FFS/ARM64EC routing, CHPE disabling policy, restore call, or instruction-cache flush call changed. |
| Acceptance Gate | `docs/plan/check-srev-119.py` validates the draft-07 schema, official references, local `NtProtectVirtualMemory` / `NT_SUCCESS` typedef shape, checked writable-protection gates in `WriteMemorySafe`, `InitSyscalls`, and `DisableCHPE`, preservation of instruction-cache flush calls, preserved SREV-106 ARM64EC context, stale unchecked local protect-write pattern removal, and ledger entry; `docs/plan/check-srev-119.sh` is the matrix wrapper. Runtime/build gate: Windows x86/x64/ARM64 low-level build for `init.c`, normal sandbox process startup with syscall hooks enabled and disabled, ARM64EC/CHPE startup where available, protection-failure instrumentation proving no write occurs after failed writable-protection transition, and Driver Verifier / loader-lock observation during early process initialization. |
