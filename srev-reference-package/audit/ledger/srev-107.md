### SREV-107: DriverAssist Host Inject Restart Coalescing

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official SCM enumeration, service open/control/start, and Sleep timing shape; needs Windows host-injected service restart runtime proof |
| Evidence | `Sandboxie/core/svc/DriverAssist.cpp` receives `SVC_CONFIG_UPDATED`, refreshes ini/syscall state, and then gates host-injected service restart work. The old `JobCounter` comment promised that the first caller waited until the last refresh before starting the job, but later callers incremented and immediately decremented the counter, so this was not a real quiet-window coalescer. The wrapped operation enumerates active Win32 services and may call `ControlService` / `StartServiceW`; Microsoft documents SCM control notifications as serial and says `ControlService` and `StartServiceW` can block for 30 seconds while another service is busy handling a control code. |
| Data | `DriverAssist::MsgWorkerThread`, `SVC_CONFIG_UPDATED`, `SbieIniServer::NotifyConfigReloaded`, `SbieDll_InjectLow_InitSyscalls(TRUE)`, `DriverAssist::RestartHostInjectedSvcs`, `RestartGeneration`, `RestartWorkerActive`, `m_critSecHostInjectedSvcs`, `HostInjectProcessUtil.cpp` `BuildSvcSet`, `g_setSvcNames`, `IsSvcInjected`, `RestartService`, `OpenSCManagerW`, `EnumServicesStatusExW`, `OpenService`, `ControlService`, and `StartServiceW`. |
| Schema | `DRIVERASSIST_HOST_INJECT_RESTART_COALESCING` says each config update increments a generation counter; only one restart worker may be active; the worker waits for a 250ms quiet window before entering SCM work; the worker must not hold `m_critSecHostInjectedSvcs` while sleeping; SCM enumeration/stop/start runs under `m_critSecHostInjectedSvcs`; if a new generation appears while SCM work is running, a worker must run another quiet-window pass; if another worker claims the new generation, the current worker may exit; HostInjectProcess matching and service restart policy must not change. |
| Topology | Every config-update request increments `RestartGeneration`. The first thread that changes `RestartWorkerActive` from 0 to 1 becomes the active worker. It repeatedly samples `RestartGeneration`, sleeps 250ms, and retries until no new generation appears during the sleep interval. It then enters `m_critSecHostInjectedSvcs`, calls `::RestartHostInjectedSvcs()`, leaves the critical section, releases `RestartWorkerActive`, and either exits if no newer generation exists or reclaims/defers worker ownership for the next quiet-window pass. The global restart job still builds the HostInjectProcess set, enumerates active Win32 services, skips `SBIESVC`, compares service names, probes `SbieDll.dll` injection state, and stops/starts only services whose injection state mismatches policy. |
| Logic Risk | The old counter made the expensive SCM job race against reload bursts. It could run based on a transient count rather than a stable post-burst config state. It also described a "waits until the last one" behavior that the implementation did not actually provide. Because service control work is serial inside SCM and can block, repeated incidental restarts are a correctness and availability risk for host-injected services. |
| Official Shape | `docs/plan/srev-107-driverassist-host-inject-restart-coalescing.md` records Microsoft `EnumServicesStatusExW`, `OpenSCManagerW`, `OpenServiceW`, `ControlService`, `StartServiceW`, and `Sleep` references. `docs/plan/srev-107-driverassist-host-inject-restart-coalescing.schema.json` records the JSON Schema draft-07 local `DRIVERASSIST_HOST_INJECT_RESTART_COALESCING` contract. |
| Fix | `DriverAssist::RestartHostInjectedSvcs` now uses `RestartGeneration` and `RestartWorkerActive`. Every request increments the generation; a single active worker waits until the generation is unchanged across a 250ms interval, then runs `::RestartHostInjectedSvcs()` under `m_critSecHostInjectedSvcs`. If new config-update requests arrive while SCM work is running, the current worker runs or defers another quiet-window pass instead of dropping the request. No HostInjectProcess config parsing, service matching, module-injection detection, SCM enumeration, service stop/start access mask, or service restart policy changed. |
| Acceptance Gate | `docs/plan/check-srev-107.py` validates the draft-07 schema, official references, generation/active-worker source topology, 250ms quiet-window loop, critical-section placement around SCM work only, stale workaround wording removal, preservation of `HostInjectProcessUtil.cpp` policy, and ledger entry; `docs/plan/check-srev-107.sh` is the matrix wrapper. Runtime gate: Windows service matrix with rapid config reload bursts, reload during an active SCM restart pass, host-injected service that lacks `SbieDll`, service that should no longer be injected, `SERVICE_WIN32_SHARE_PROCESS`, service stop timeout / `ERROR_SERVICE_REQUEST_TIMEOUT`, access-denied service, and observation that exactly the stable post-burst `HostInjectProcess` policy is applied. |
