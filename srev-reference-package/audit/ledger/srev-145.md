### SREV-145: GUI Async Message Return ABI

| Field | Content |
|---|---|
| Severity | [major] |
| Status | patched source-level after official PostMessageW, SendNotifyMessageW, PeekMessageW, GetMessageW, MessageBoxW, MessageBoxExW, PostThreadMessageW, and DispatchMessageW review; needs Windows GUI message hook runtime proof |
| Evidence | `Sandboxie/core/dll/gui_p.h` was the top unnamed reviewable core file after SREV-144. It is the private GUI hook surface that declares `P_*` User32 function pointer types, the `__sys_*` real API slots, and the hook wrapper interfaces used by `Sandboxie/core/dll/gui.c`, `Sandboxie/core/dll/guimsg.c`, `guiprop.c`, `guihook.c`, and related GUI modules. Before this SREV, `P_SendNotifyMessage`, `P_PostMessage`, `P_PeekMessage`, `P_GetMessage`, `P_MessageBoxW`, and `P_MessageBoxExW` were declared as returning `LRESULT`, while Microsoft documents the first four as `BOOL` and the message-box APIs as `int`. `Sandboxie/core/dll/guimsg.c` also declared and defined `Gui_SendNotifyMessageA/W` and `Gui_PostMessageA/W` as `LRESULT`, even though these wrappers replace APIs whose official return shape is `BOOL`. |
| Data | `P_SendNotifyMessage`, `P_PostMessage`, `P_PostThreadMessage`, `P_DispatchMessage`, `P_PeekMessage`, `P_GetMessage`, `P_MessageBoxW`, `P_MessageBoxExW`, `__sys_SendNotifyMessageA/W`, `__sys_PostMessageA/W`, `__sys_PeekMessageA/W`, `__sys_MessageBoxW`, `__sys_MessageBoxExW`, `Gui_SendNotifyMessageA/W`, `Gui_PostMessageA/W`, `Gui_SendPostMessageCommon`, `Gui_MessageBoxW`, and `Gui_MessageBoxExW`. |
| Schema | `GUI_ASYNC_MESSAGE_RETURN_ABI` says `gui_p.h` owns the private User32 function-pointer return ABI used by the GUI hook surface; `PostMessageA/W` and `SendNotifyMessageA/W` return `BOOL`, not `LRESULT`; `PeekMessageA/W` and `GetMessageA/W` return `BOOL`, not `LRESULT`; `MessageBoxW` and `MessageBoxExW` return `int`, not `LRESULT`; `PostThreadMessageA/W` already returns `BOOL`, and `DispatchMessageA/W` remains `LRESULT`; hook wrappers that replace `PostMessageA/W` and `SendNotifyMessageA/W` must expose the same `BOOL` return shape as the APIs they replace; the shared `Gui_SendPostMessageCommon` internal route may keep `LRESULT` because it also serves `SendMessage` and `SendMessageTimeout` paths. |
| Topology | Legal return-shape flow is `gui.c` imports User32 exports into `__sys_*` slots using `gui_p.h` `P_*` typedefs, `SBIEDLL_HOOK_GUI` installs GUI wrappers with matching public API return shape, `PostMessage` / `SendNotifyMessage` wrappers return `BOOL` to caller, `PeekMessage` / `GetMessage` real slots are called through `BOOL` typedefs, `MessageBox` real slots are called through `int` typedefs, and `DispatchMessage` remains `LRESULT`. |
| Logic Risk | This is a hook ABI surface. Even when most paths currently return only `0` or `1`, a private typedef that does not match the replaced User32 API leaves the hook boundary dependent on accidental calling-convention tolerance. On x64, a caller of a `BOOL` API consumes a 32-bit result, while a local `LRESULT` prototype models a pointer-sized result. The owner-local fix is to align the private typedef table and the affected wrappers with the official return types without changing message routing, GUI proxy policy, DDE behavior, or `Gui_SendPostMessageCommon` internals. |
| Official Shape | `docs/plan/srev-145-gui-async-message-return-abi.md` records Microsoft `PostMessageW`, `SendNotifyMessageW`, `PeekMessageW`, `GetMessageW`, `MessageBoxW`, `MessageBoxExW`, `PostThreadMessageW`, and `DispatchMessageW` references. `docs/plan/srev-145-gui-async-message-return-abi.schema.json` records the JSON Schema draft-07 local `GUI_ASYNC_MESSAGE_RETURN_ABI` contract. |
| Fix | `gui_p.h` now declares `P_SendNotifyMessage`, `P_PostMessage`, `P_PeekMessage`, and `P_GetMessage` as returning `BOOL`, and declares `P_MessageBoxW` / `P_MessageBoxExW` as returning `int`. `guimsg.c` now declares and defines `Gui_SendNotifyMessageA/W` and `Gui_PostMessageA/W` as returning `BOOL`. The `SendNotifyMessage` wrappers cast the shared `Gui_SendPostMessageCommon` result to `BOOL`; the `PostMessage` wrappers keep their existing local result logic and return it through the official `BOOL` shape. |
| Acceptance Gate | `docs/plan/check-srev-145.py` validates the draft-07 schema, official references, corrected `gui_p.h` typedefs, preservation of `PostThreadMessage` and `DispatchMessage` return shapes, corrected `guimsg.c` wrapper declarations and definitions, preservation of `Gui_SendPostMessageCommon` as `LRESULT`, existing MessageBox wrappers as `int`, and the ledger fragment; `docs/plan/check-srev-145.sh` is the matrix wrapper. Runtime/build gate: Windows GUI DLL build; `PostMessageA/W` and `SendNotifyMessageA/W` hooks return zero/nonzero exactly like User32; direct same-box, proxy, broadcast, and DDE compatibility paths keep their previous message routing; `PeekMessage`, `GetMessage`, and `MessageBox` real API slots still import and call successfully; x86 and x64 GUI hook smoke proves no calling-convention regression. |
