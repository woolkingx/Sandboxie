### SREV-106: Low Inject ARM64EC Syscall Entrypoint

| Field | Content |
|---|---|
| Severity | [minor] |
| Status | source-level classified after official Arm64EC ABI, FFS, and Nt/Zw native-service shape; comment-only source clarification, no behavior change |
| Evidence | `Sandboxie/core/low/inject.c` chooses injection-time pointers for `NtProtectVirtualMemory`, `NtRaiseHardError`, and `NtDeviceIoControlFile` after SbieLow syscall state has been prepared. The uncovered comment said FFS resolution "does not work for syscalls". Microsoft documents Arm64EC interoperability, call checkers, exit thunks, and fast-forward sequences for ordinary hybrid exports; Microsoft also documents native system services as Nt/Zw routines reached by user-mode applications through system calls. Local source shows syscall exports are not ordinary FFS-only exports in this path: `lowlevel_inject.c` captures native Nt* entrypoints and EC syscall wrapper metadata, `init.c` installs `NtDeviceIoControlFileEC` / `EcExitThunkPtr` state, and `inject.c` uses the pre-captured native/EC entrypoints for injection-time calls. |
| Data | `Sandboxie/core/low/inject.c`, `InitInject`, `INJECT_DATA`, `SBIELOW_DATA`, `data->flags.is_wow64`, `FindDllExport(ntdll_base, ...)`, `Hook_GetFFSTarget`, `NativeNtProtectVirtualMemory`, `NativeNtRaiseHardError`, `NtDeviceIoControlFile`, `NtDeviceIoControlFileEC`, `EcExitThunkPtr`, `SbieDll_GetEcExitThunkPtr`, `NATIVE_FUNCTION_NAMES`, and `DetourFunc`. |
| Schema | `LOW_INJECT_ARM64EC_SYSCALL_ENTRYPOINT` says ARM64EC allows x64 and Arm64EC code to interoperate in one process; ARM64EC indirect calls use call checkers and exit thunks; fast-forward sequences are small x64 functions that transfer execution to the real Arm64EC function; ordinary ARM64EC exports may be FFS-resolved to native EC targets; native system services use Nt/Zw entrypoints and user-mode applications reach them through system calls; Nt* syscall exports in SbieLow are routed through local syscall-wrapper state rather than ordinary FFS-only export resolution; WOW64 injection resolves 32-bit ntdll Nt* exports from `ntdll_wow64_base`; native and ARM64EC injection use pre-captured native or EC entrypoints from `SBIELOW_DATA`; `NtDeviceIoControlFile` may point to the EC wrapper installed by `PrepSyscalls`. |
| Topology | `lowlevel_inject.c` captures ntdll base, native Nt* entrypoints, and syscall data; ARM64EC appends EC syscall wrapper data and `EcExitThunkPtr`; `init.c` prepares SbieLow syscall wrapper state and may point `data->NtDeviceIoControlFile` at `NtDeviceIoControlFileEC`; `inject.c` resolves 32-bit ntdll exports for WOW64 targets but uses `SBIELOW_DATA` native/EC entrypoints for native / ARM64EC targets; `DetourFunc` then restores the hook and loads `SbieDll.dll`. |
| Logic Risk | The old wording made the rule sound like a failed FFS implementation detail. The real boundary is that ordinary hybrid exports and Nt* syscall entrypoints belong to different local owners. Retrying FFS parsing for syscall exports would bypass the SbieLow syscall-wrapper state prepared from driver/runtime data. |
| Official Shape | `docs/plan/srev-106-low-inject-arm64ec-syscall-entrypoint.md` records Microsoft Arm64EC, Arm64EC ABI, `hybrid_patchable` / FFS, Nt/Zw native-service, and public kernel DDI index references. `docs/plan/srev-106-low-inject-arm64ec-syscall-entrypoint.schema.json` records the JSON Schema draft-07 local `LOW_INJECT_ARM64EC_SYSCALL_ENTRYPOINT` contract. |
| Fix | Comment-only source clarification: the stale "does not work for syscalls" wording now states that ordinary ARM64EC exports can be FFS-resolved, while Nt* syscall exports are routed through SbieLow syscall-wrapper state and keep the pre-captured native/EC entrypoints for injection-time calls. No pointer assignment, FFS parsing, syscall wrapper construction, hook target, detour patch size, DLL load, or error-reporting behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-106.py` validates the draft-07 schema, official references, WOW64 export path, native / ARM64EC pre-captured entrypoint path, local EC syscall-wrapper preparation, FFS helper boundary, stale "does not work" wording removal, and ledger entry; `docs/plan/check-srev-106.sh` is the matrix wrapper. Runtime gate: Windows on Arm matrix with ARM64EC target process, x64-emulated target process, WOW64 target process where applicable, `NtProtectVirtualMemory` hook restore, `NtRaiseHardError` injection failure path, `NtDeviceIoControlFile` driver call path, FFS-resolved ordinary exports, SbieLow syscall hook enabled and disabled, and Driver Verifier / loader-lock observation during early process initialization. |
