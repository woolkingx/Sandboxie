### SREV-326: Secure BITS/WUAU AccessCheckByType Bypass

| Field | Content |
|---|---|
| Severity | [medium] |
| Status | patched source-level native access-check first path; needs Windows runtime proof |
| Evidence | `Ldr_NtAccessCheckByType` has a Windows 8.1+ allowlist for `DLL_IMAGE_SANDBOXIE_BITS`, `DLL_IMAGE_SANDBOXIE_WUAU`, and `DLL_IMAGE_WUAUCLT`. The source now calls `Ldr_TestToken` and native `__sys_NtAccessCheckByType` before any synthetic grant. If native succeeds, native `GrantedAccess` / `AccessStatus` / return status is returned. If native itself fails, the compatibility fallback synthesizes `GrantedAccess` from `DesiredAccess`, maps `MAXIMUM_ALLOWED` to `GenericMapping->GenericAll | (DesiredAccess & ~MAXIMUM_ALLOWED)`, sets `AccessStatus = STATUS_SUCCESS`, clears last error, and returns `STATUS_SUCCESS`. |
| Data | `Ldr_NtAccessCheckByType`, `Dll_OsBuild >= 9600`, `DLL_IMAGE_SANDBOXIE_BITS`, `DLL_IMAGE_SANDBOXIE_WUAU`, `DLL_IMAGE_WUAUCLT`, `DesiredAccess`, `MAXIMUM_ALLOWED`, `GENERIC_MAPPING.GenericAll`, `GrantedAccess`, `AccessStatus`, `STATUS_SUCCESS`, `SetLastError(0)`, `Ldr_TestToken`, and `__sys_NtAccessCheckByType`. |
| Schema | `SECURE_BITS_WUAU_ACCESSCHECK_BYPASS` says official access-check semantics are descriptor/token/object-type/generic-mapping decisions; `MAXIMUM_ALLOWED` is not equivalent to blindly granting `GenericAll`; the BITS/WUAU branch is a local compatibility bypass, not a proven access-check implementation; the bypass is limited to BITS, Sandboxie WUAU, and `wuauclt`; allowlisted callers must try `Ldr_TestToken` plus native `__sys_NtAccessCheckByType` before using the synthetic compatibility grant; the synthetic `MAXIMUM_ALLOWED -> GenericAll` fallback is allowed only when the native API call itself fails; all other callers must continue through `Ldr_TestToken` and native `__sys_NtAccessCheckByType`; the runtime matrix must cover Windows versions, allowlisted callers, non-allowlisted callers, requested-access shapes, security descriptors, token shapes, output contracts, and regression evidence. |
| Topology | Normal route is `caller -> Ldr_NtAccessCheckByType -> Ldr_TestToken(ClientToken, real token) -> __sys_NtAccessCheckByType -> native descriptor/token access decision`. Allowlisted route is `Windows 8.1+ BITS/WUAU/WUAUCLT image -> Ldr_NtAccessCheckByType -> Ldr_TestToken(ClientToken, real token) -> __sys_NtAccessCheckByType -> if native call succeeds: native descriptor/token access decision -> if native call fails: synthetic compatibility grant`. |
| Logic Risk | The old branch was not equivalent to documented access-check semantics because it ignored the security descriptor, token groups, privileges, owner checks, object-type hierarchy, and denial-specific `AccessStatus`. The source now restores the owner order for allowlisted callers: native descriptor/token/object-type access check first, synthetic compatibility grant only if the native API call itself fails. Windows runtime proof remains required to show BITS/WUAU compatibility is preserved. |
| Official Shape | `docs/plan/srev-326-secure-bits-wuau-accesscheck-bypass.md` records Microsoft `AccessCheckByType`, `GENERIC_MAPPING`, and `SeAccessCheck` references. It also records that no public Microsoft Win32 API page was found for `NtAccessCheckByType` during this pass. `docs/plan/srev-326-secure-bits-wuau-accesscheck-bypass.schema.json` records the JSON Schema draft-07 local `SECURE_BITS_WUAU_ACCESSCHECK_BYPASS` contract. |
| Shared Runtime Capture Evidence | Runtime records use `docs/plan/srev-326-327-secure-runtime-capture.schema.json`; `docs/plan/srev-326-327-secure-runtime-capture-playbook.md` is the capture procedure; `docs/plan/check-srev-326-327-secure-runtime-capture.sh` validates the shared secure evidence contract. |
| Fix | Source-level native-first access-check path. The allowlisted BITS/WUAU/WUAUCLT branch now calls `Ldr_TestToken` and `__sys_NtAccessCheckByType` before any synthetic grant. If the native API succeeds, its descriptor/token/object-type result is returned. If the native API itself fails, the old synthetic `MAXIMUM_ALLOWED -> GenericAll` compatibility behavior remains as the fallback. No image predicate, OS-build gate, fallback `MAXIMUM_ALLOWED` handling, fallback `GrantedAccess` assignment, fallback `AccessStatus`, fallback `SetLastError`, non-allowlisted `Ldr_TestToken`, or non-allowlisted native forwarding behavior changed. |
| Acceptance Gate | `docs/plan/check-srev-326.py` validates the draft-07 schema, official references, source comment, unchanged BITS/WUAU/WUAUCLT allowlist, unchanged fallback `MAXIMUM_ALLOWED`/`GenericAll` synthetic grant, native access-check first ordering for allowlisted callers, preserved non-allowlisted `Ldr_TestToken` and native forwarding fallback, stale uncertainty comment removal, runtime matrix, combined ledger entry, and split ledger fragment; `docs/plan/check-srev-326.sh` is the targeted wrapper. `docs/plan/check-srev-326-327-secure-runtime-capture.sh` validates the shared secure runtime playbook and machine-readable evidence schema `docs/plan/srev-326-327-secure-runtime-capture.schema.json`. Windows gate: run the BITS/WUAU/WUAUCLT compatibility matrix on Windows 8.1+ and Windows 10/11, with allowlisted caller native-first proof, fallback proof only when native fails, non-allowlisted caller negative controls, allow/deny/NULL/owner-specific/object-type security descriptors, specific/generic/MAXIMUM_ALLOWED desired access, sandboxed/real/admin/non-admin token shapes, `GrantedAccess` / `AccessStatus` / `LastError` / return-status readback, and native forwarding regression. |
